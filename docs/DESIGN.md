# DESIGN.md — 디자인 시스템 사용 규칙

> 이 문서는 프로젝트와 무관하게 재사용하는 **규칙과 이유**만 담는다.
> 토큰 값·컴포넌트 목록 같은 **수치와 목록은 적지 않는다.** Figma가 원본이며 MCP로 조회한다.
> Figma 라이브러리 URL과 코드 토큰 위치는 `docs/PROJECT.md`를 따른다.

## 1. 원본(Source of Truth)
- 값의 원본은 Figma다. 이 문서나 다른 md에 값을 복사해 두지 않는다. (복사하면 Figma와 어긋난다)
- 코드의 토큰 파일은 Figma 변수를 옮긴 결과물이다. 둘이 다르면 Figma를 기준으로 하고 사용자에게 알린다.
- IMPORTANT: 코드 토큰 파일(`tokens.css`와 참조 파일 `tokens.ts`·`tokens.js`)은 `token-sync` 스킬로만 만든다. 손으로 고치지 않는다. (다음 동기화 때 사라진다)

## 2. 값 조회 방법 (Figma MCP)
| 필요한 정보 | 조회 방법 |
|---|---|
| 화면 구조·스타일 | 화면 명세의 Figma 노드 → `get_design_context` |
| 화면에 쓰인 변수의 최종 값 | `get_variable_defs` |
| 변수 전체 (컬렉션·모드·별칭) | `token-sync` 스킬 (`use_figma` 읽기 전용) |
| 기존 컴포넌트·스타일 검색 | `search_design_system` |
| 컴포넌트 ↔ 코드 매핑 | `get_code_connect_map` |
| 시각 비교 | `get_screenshot` (주소로 이미지를 받지 못하는 환경이면 `enableBase64Response: true`로 대화 안에서 받는다. 그것도 안 되면 사람에게 캡처를 요청한다) |

- IMPORTANT: 필요한 노드만 조회한다. 페이지·파일 전체를 조회하지 않는다. (토큰 절감)
- 같은 작업 안에서 이미 조회한 값은 다시 조회하지 않는다.

## 3. 토큰 규칙

### 3-1. 사용
- IMPORTANT: 색상·간격·폰트·반경·그림자는 코드 토큰으로만 쓴다. 숫자·HEX 직접 입력 금지.
- 의미 토큰(semantic, 예: `color.text.primary`)을 우선 쓴다. 원시 토큰(primitive, 예: `blue.500`)은 의미 토큰이 없을 때만 쓴다.
- Figma 변수명과 코드 토큰명은 3-2 이름 규칙으로 대응시켜 찾는다. 대응하는 토큰이 없으면 임의로 만들지 않고 묻는다.
- Figma 변수에는 있는데 코드 토큰 파일에 없으면 토큰 파일이 오래된 것이다. 토큰 파일을 고치지 않고 `token-sync`를 안내한다.
- 비슷한 값이 있다고 다른 용도의 토큰을 빌려 쓰지 않는다. (예: 에러 색을 경고에 사용 금지)
- 글자: Figma 텍스트 레이어에 텍스트 스타일이 붙어 있으면 그 스타일의 토큰을 쓴다. 글자 크기·굵기 변수를 하나씩 골라 쓰지 않는다. (화면·마크업은 묶음 클래스, 컴포넌트 스타일 안에서는 속성별 변수 — 3-3)
- 그림자: 효과 스타일 토큰(`--shadow-*`)만 쓴다. 대응 토큰이 없으면 8번 절차를 따른다.
- 디자인 시스템이 토큰으로 두지 않는 종류(폭·높이·z-index 등)는 3-4를 따른다.

### 3-2. Figma 변수 → 코드 토큰 변환
> `token-sync` 스킬이 이 규칙대로 토큰 파일을 만든다. 변환은 `.claude/skills/token-sync/convert-tokens.mjs`가 한다. 같은 Figma 변수는 언제 변환해도 같은 결과가 나와야 한다. 규칙을 고치면 스크립트도 함께 고친다.

**대상**
- `docs/PROJECT.md` "Figma 변수 파일"의 로컬 변수 전체
- 제외: 게시에서 숨긴 변수 중 아무 토큰도 가리키지 않는 것, 불리언 변수, 9번에 적은 제외 컬렉션
- 게시에서 숨긴 변수라도 동기화하는 변수·스타일이 별칭으로 가리키면 원시 토큰으로 포함한다. (원시 색을 숨기고 의미 토큰만 공개하는 디자인 시스템이 많다)

**이름**
| Figma 변수 | CSS 변수 | 참조 파일 |
|---|---|---|
| `color/text/primary` | `--color-text-primary` | `tokens.color.text.primary` |
| `color/bg subtle` | `--color-bg-subtle` | `tokens.color.bgSubtle` |
| `blue/500` | `--blue-500` | `tokens.blue['500']` |
| `spacing/0.5` | `--spacing-0_5` | `tokens.spacing['0_5']` |

- 소문자로 바꾸고, `/`와 공백은 `-`, `.`은 `_`로 바꾼다. 그 밖의 특수문자는 지운다.
- 컬렉션 이름은 넣지 않는다.
- 참조 파일은 `/`로 나눈 단계를 객체 단계로 쓴다. 단계 안의 `-`는 camelCase로 바꾸고, 숫자로 시작하는 단계는 문자열 키로 쓴다.
- 변환한 이름이 겹치거나, 한 이름이 값이면서 하위 단계를 가지면 변환하지 않고 멈춘다. (Figma 이름을 정리해야 한다)

**값**
| 변수 종류 | 출력 |
|---|---|
| 색상 | 소문자 `#rrggbb`, 투명도가 있으면 `#rrggbbaa` |
| 숫자 — 간격·반경·크기·글자 크기·행간·자간·선 두께 | `px` (9번에서 rem으로 바꿀 수 있음) |
| 숫자 — 글자 굵기·불투명도 등 단위 없는 값 | 숫자 그대로. 불투명도가 0~100 값이면 100으로 나눈다 |
| 문자열 — 글꼴 | 따옴표로 감싼다. 대체 글꼴은 9번에 적는다 |
| 문자열 — 글자 굵기 이름 | Thin 100 · ExtraLight 200 · Light 300 · Regular 400 · Medium 500 · SemiBold 600 · Bold 700 · ExtraBold 800 · Black 900 (띄어쓰기 무시). 그 밖의 이름은 묻는다 |

- 숫자 종류는 변수의 적용 범위(scopes)로 판단한다. 적용 범위가 "모든 범위"이거나 없으면 이름 첫 단계(`spacing`, `radius`, `border`, `size`, `font-size`, `line-height`, `letter-spacing`, `font-weight`, `opacity` 등)로 판단하고, 그래도 모르면 멈추고 묻는다. 답은 9번 "숫자 단위 지정"에 적는다.

**별칭**
- 다른 변수를 가리키는 값은 `var(--대상)`으로 쓴다. 최종 값으로 풀어 쓰지 않는다.
- 대상이 동기화 범위 밖(다른 파일·라이브러리 변수, 찾을 수 없는 변수, 9번 제외 컬렉션)이면 멈춘다.

**모드**
- 컬렉션의 기본 모드 값은 `:root`에, 나머지 모드 값은 `[data-theme="<모드 이름>"]` 블록에 쓴다. 모드 이름도 이름 규칙으로 바꾼다. (예: `Dark` → `dark`) 바꿀 수 없으면(예: 한글 모드 이름) 9번 "모드 이름"에 코드 값을 정한다.
- 기본 모드와 값이 같은 변수는 모드 블록에 다시 쓰지 않는다.
- 모드가 2개 이상인 컬렉션이 둘 이상이면 9번에 컬렉션별 속성 이름을 정한 뒤 진행한다.
- 참조 파일의 값은 `var()` 문자열이므로 모드와 관계없이 하나다.

**순서·파일**
- 순서: 원시 토큰(모든 모드 값이 직접 값) → 의미 토큰(별칭 값이 하나라도 있음). 각각 이름순.
- 만드는 파일은 `docs/PROJECT.md`의 퍼블 언어·TypeScript로 정한다.

| 퍼블 언어 | 만드는 파일 |
|---|---|
| JS(HTML·CSS·JS) | `tokens.css`만 |
| React·Vue + TypeScript | `tokens.css` + `tokens.ts` (`as const` 객체) |
| React·Vue, TypeScript 미사용 | `tokens.css` + `tokens.js` (`as const` 없이 같은 객체) |

- `tokens.css`는 CSS 변수 정의, 참조 파일은 같은 토큰의 `var()` 참조 객체다.
- 텍스트 스타일이 있으면 모든 퍼블 언어에서 `text-styles.css`를 추가로 만든다. (3-3)
- 모든 파일 맨 위에 자동 생성 표시를 넣는다.

```css
/* 자동 생성 — 직접 고치지 마세요. token-sync 스킬로 갱신합니다. */
:root {
  --blue-500: #2563eb;
  --gray-50: #f9fafb;
  --gray-900: #111827;
  --spacing-4: 16px;
  --color-text-primary: var(--gray-900);
}

[data-theme="dark"] {
  --color-text-primary: var(--gray-50);
}
```

```ts
// 자동 생성 — 직접 고치지 마세요. token-sync 스킬로 갱신합니다.
export const tokens = {
  blue: { '500': 'var(--blue-500)' },
  gray: { '50': 'var(--gray-50)', '900': 'var(--gray-900)' },
  spacing: { '4': 'var(--spacing-4)' },
  color: { text: { primary: 'var(--color-text-primary)' } },
} as const;
```

### 3-3. Figma 스타일 → 코드 토큰 변환
> `token-sync` 스킬이 3-2 변수 토큰과 함께 만든다. 내보내기는 `export-tokens.js`(읽기 전용), 변환은 `convert-tokens.mjs`가 한다.

**대상**
- `docs/PROJECT.md` "Figma 스타일 파일"의 로컬 **텍스트 스타일**과 **효과 스타일 중 그림자**(드롭 섀도·안쪽 그림자)
- 제외하고 목록으로 보고: 블러 효과(레이어·배경 블러), 9번에 적은 제외 스타일
- 색 스타일은 옮기지 않는다. 색의 원본은 변수다. 색 스타일만 있는 디자인 시스템이면 변수로 바꿔 달라고 DS 변경 요청을 만든다. (`docs/ds-requests/`)

**이름**
- 3-2 이름 규칙으로 바꾼 뒤 종류별 앞머리를 붙인다. 텍스트 `text-`, 그림자 `shadow-` (9번에서 바꿀 수 있다)
- Figma 이름의 첫 단계가 앞머리와 같으면 다시 붙이지 않는다. (예: `Shadow/Card` → `shadow-card`)
- 변수 토큰 이름과 겹치면 변환하지 않고 멈춘다.

| Figma 스타일 | CSS 변수 | 묶음 클래스 | 참조 파일 |
|---|---|---|---|
| 텍스트 `Body/M` | `--text-body-m-font-family`, `-font-size`, `-font-weight`, `-line-height`, `-letter-spacing` (+ 필요하면 `-font-style`, `-text-transform`) | `.text-body-m` | `tokens.text.body.m.fontSize` |
| 효과 `Shadow/Card` | `--shadow-card` | 없음 | `tokens.shadow.card` |

**텍스트 스타일 값**
| 항목 | 출력 |
|---|---|
| 글꼴 | 따옴표로 감싼다. 대체 글꼴은 9번 |
| 크기 | px (9번에서 rem으로 바꿀 수 있음) |
| 굵기 | 글꼴 스타일 이름을 3-2 굵기 이름 표로 바꾼다. 이름에 Italic이 있으면 `-font-style: italic`도 만든다 |
| 행간 | 픽셀 → px / 퍼센트 → 단위 없는 비율 (150% → `1.5`) / 자동 → `normal` |
| 자간 | 픽셀 → px / 퍼센트 → em (-2% → `-0.02em`) |
| 대소문자 | 원래대로가 아닐 때만 `-text-transform` (대문자 `uppercase`, 소문자 `lowercase`, 첫 글자 `capitalize`) |
| 꾸밈 | 밑줄·취소선일 때만 `-text-decoration` (`underline`, `line-through`) |

**그림자 값**
- 그림자 하나는 `<x> <y> <흐림> <퍼짐> <색>` 순서의 `box-shadow` 값이다. 숫자는 px, 색은 3-2 색 규칙.
- 안쪽 그림자는 앞에 `inset`을 붙인다. 여러 겹이면 Figma 순서대로 쉼표로 잇는다. 숨긴 효과는 뺀다.

**변수 연결**
- 스타일 값에 변수가 연결돼 있으면 값 대신 `var(--변수 토큰)`을 쓴다. (3-2 별칭과 같다) 연결 대상이 동기화 범위 밖이면 멈춘다.

**파일**
- CSS 변수는 `tokens.css`에 변수 토큰 다음에 쓴다. (스타일이 변수를 가리키므로) 텍스트 → 그림자 순, 각각 이름순.
- 묶음 클래스는 `text-styles.css`에 쓴다. 클래스는 위 CSS 변수만 쓴다. 파일 위치는 다른 토큰 파일과 같은 폴더(`docs/PROJECT.md` "코드 토큰 위치")다.

```css
/* text-styles.css — 자동 생성 — 직접 고치지 마세요. token-sync 스킬로 갱신합니다. */
.text-body-m {
  font-family: var(--text-body-m-font-family);
  font-size: var(--text-body-m-font-size);
  font-weight: var(--text-body-m-font-weight);
  line-height: var(--text-body-m-line-height);
  letter-spacing: var(--text-body-m-letter-spacing);
}
```

- 참조 파일(`tokens.ts`·`tokens.js`)에는 `text`·`shadow` 단계로 같은 토큰의 `var()`를 넣는다. 클래스 이름은 넣지 않는다.

### 3-4. 토큰이 없는 종류 (레이아웃 값 파일)
> 디자인 시스템이 토큰을 두지 않는 종류가 흔하다. 예) 본문·영역의 폭, 요소 높이, 아이콘 크기, 쌓임 순서(z-index). 이런 값까지 하나씩 DS 변경 요청으로 막으면 퍼블을 시작할 수 없어서, 숫자를 한 곳에 모아 이름을 붙인다.
- 먼저 토큰을 찾는다. 같은 용도의 토큰이 있으면 그것을 쓴다. 이 절은 **그 종류의 토큰이 디자인 시스템에 없을 때만** 쓴다.
- 숫자는 **레이아웃 값 파일 한 곳**에만 쓴다. 위치는 `docs/PROJECT.md` "레이아웃 값 파일". (비어 있으면 `<퍼블 소스 폴더>/styles/layout.css`, 종류별 폴더면 `css/layout.css`)
- 파일 안에서는 CSS 변수로 이름을 붙인다. 이름은 `--layout-<용도>`. 값 옆 주석에 Figma 노드와 DS 변경 요청 ID(있으면)를 적는다.
  예)
  ```css
  :root {
    --layout-pc-content-width: 600px; /* Figma 1234:5678 · DS-001 */
    --layout-z-sticky: 10;            /* 하단 고정 버튼 */
    --layout-z-dialog: 30;            /* 알럿 딤 */
  }
  ```
- 컴포넌트·공통 스타일은 `var(--layout-*)`만 쓴다. 컴포넌트에 숫자를 직접 쓰지 않는다.
- 이름은 용도로 짓는다. 값으로 짓지 않는다. (`--layout-600` 금지) 같은 값이라도 용도가 다르면 따로 둔다.
- 쌓임 순서(z-index)는 이 파일에서 한눈에 비교되게 모은다.
- 이 종류를 디자인 시스템에 넣을지는 DS 변경 요청을 **종류마다 한 번** 낸다. (8번) 값마다 요청하지 않는다. 요청이 열려 있어도 이 파일로 진행할 수 있다. (요청 파일의 가정 진행, `docs/ds-requests/_index.md` 2번)
  - 반영되면 `token-sync` 뒤 이 파일의 값을 토큰 `var()`로 바꾸거나, 사용처를 토큰으로 바꾸고 변수를 지운다.
  - 기각되면 이 파일을 그대로 쓴다.
- 레이아웃 값 파일은 하드코딩 점검(`check-pub` P9, `check-hardcoded` 훅, `ds-check`)에서 빠진다. 다른 파일의 숫자는 그대로 위반이다.
- 색·간격·글자·반경·그림자는 이 절의 대상이 아니다. 토큰이 없으면 8번 절차를 따른다.
- **가정 값:** 간격·여백·반경처럼 토큰 종류는 있는데 맞는 값이 없고, DS 변경 요청을 가정으로 진행하기로 했으면(8번) 그 숫자도 이 파일에 모은다. 이름은 `--assume-<종류>-<용도>`, 주석에 `가정(<요청 ID>)`와 Figma 노드. 컴포넌트는 `var()`만 쓴다. 한 요소의 값이 컴포넌트와 이 파일로 갈라지지 않게 한다.
  예) `--assume-space-chip-gap: 6px; /* 가정(DS-003) · Figma 1234:5678 */`
  - 요청이 반영되면 `token-sync` 뒤 사용처를 토큰으로 바꾸고 `--assume-*` 변수를 지운다. 대체·기각되면 정한 값으로 바꾼다. 남은 `--assume-*`는 열린 DS 요청이 있어야 한다.

## 4. 컴포넌트 사용 규칙
- IMPORTANT: 순서는 ① 연결 목록 확인 → ② 코드에서 기존 컴포넌트 검색 → ③ 없을 때만 새로 만든다.
  - 연결 목록: `docs/components/_index.md` 현황의 "연결 목록" (Figma 컴포넌트 세트 이름 → 코드 컴포넌트). 원본은 각 컴포넌트 명세의 `figma_name`이다.
  - Figma 인스턴스 이름이 연결 목록에 있으면 그 코드 컴포넌트를 반드시 쓴다. Figma variant 속성은 명세 4·5번 표대로 옮긴다.
  - 라이브러리 컴포넌트인데 연결이 없으면 멈추고, 새 컴포넌트 후보로 보고한다. (기존 코드에 있으면 짧은 명세로 연결만 등록한다)
  - 라이브러리 컴포넌트가 아니라 화면에 직접 그린 요소면 멈추고, 8번 절차를 따른다.
  - 인스턴스인데 이름이 지금 라이브러리의 세트 이름과 맞지 않으면(옛 컴포넌트, 이름이 바뀐 세트, 다른 파일의 컴포넌트) 멈추고 보고한다. 지금 라이브러리에 같은 역할의 세트가 있으면 그 세트의 코드 컴포넌트로 퍼블하고 8번 DS 변경 요청(Figma 인스턴스 교체)을 남긴다. 같은 역할의 세트가 없으면 직접 그린 요소와 같게 8번 절차를 따른다.
  - Code Connect를 쓰는 프로젝트(`docs/PROJECT.md`)는 `get_code_connect_map`으로도 대조한다. 둘이 다르면 컴포넌트 명세가 원본이다.
- 기존 컴포넌트를 복사해 변형하지 않는다. 필요한 변형은 props/variant로 확장하고, 확장이 어려우면 묻는다.
- 새 컴포넌트는 `templates/component-spec.md`로 명세를 먼저 쓰고 승인받는다.
- Figma 컴포넌트명과 코드 컴포넌트명을 일치시킨다.

## 5. 상태 규칙
### 5-1. 화면 상태
- 모든 화면·컴포넌트는 해당하는 상태를 빠짐없이 구현한다: 기본 / 로딩 / 빈 값 / 에러 / 비활성 / (해당 시) 점검.
- Figma에 상태 디자인이 없으면 임의로 만들지 않고 화면 명세에 "디자인 필요"로 표시한 뒤 묻는다.

### 5-2. 요소 상태 (누름·포커스·선택 등)
- Figma 컴포넌트 variant의 상태 값을 CSS에 대응시킨다. 대응은 컴포넌트 명세 5번 "CSS 대응" 칸에 적는다.

  | Figma 상태 값 (예) | CSS |
  |---|---|
  | Hover | `:hover` (터치 기기 처리는 9번 예외 "hover 처리") |
  | Pressed | `:active` |
  | Focused | `:focus-visible` |
  | Disabled | `:disabled` (버튼·입력), 그 밖은 `aria-disabled="true"` |
  | Selected·On | `aria-selected`(탭·목록 선택)·`aria-pressed`(켜고 끄는 버튼)·`aria-checked`(체크·라디오·스위치) |
  | Current | `aria-current="page"` (지금 화면을 가리키는 메뉴·탭) |
  | Error | `aria-invalid="true"` (입력란) |
- 상태 모양은 클래스가 아니라 위 의사 클래스·속성 선택자로 건다. 값은 토큰만 쓴다.
- Figma에 그 상태 variant가 없으면 모양을 만들지 않고 질문한다(`docs/questions/design.md`, 디자인 필요). 단 포커스 표시는 없애지 않는다. Figma에 없으면 프로젝트 기본 포커스 모양(9번 예외 "기본 포커스 모양")을 쓴다. (`.claude/rules/a11y.md` 3번)

### 5-3. 움직임 (전환 효과·애니메이션)
- Figma 프로토타입(Smart Animate 등)·모션 토큰에 있는 움직임만 옮긴다. 시간·이징 값은 그대로 쓰고, 토큰이 없으면 레이아웃 값 파일(3-4)에 `--layout-motion-<용도>`로 둔다. 없는 움직임은 넣지 않는다.
- 퍼블은 화면 안 요소의 움직임만 다룬다. 예) 바텀시트 올라오기, 아코디언 펼치기, 토스트 나타나기. 화면 사이 전환은 개발 몫이다.
- `prefers-reduced-motion: reduce`이면 움직임을 끄거나 투명도 변화로만 바꾼다. (`.claude/rules/a11y.md` 6번)
- 프로젝트 기본 움직임 값은 9번 예외 "기본 움직임 값"에 적는다.

## 6. 레이아웃 규칙

### 6-1. 배치
- 간격은 간격 토큰 단위로만 맞춘다. 눈대중으로 맞춘 값은 쓰지 않는다.
- Figma 오토레이아웃은 flex/grid로 옮긴다. 절대 위치는 Figma에서도 절대 위치일 때만 쓴다.
- 디바이스가 여럿이고 한 화면이 폭에 따라 모양을 바꾸면(반응형), 모양이 바뀌는 폭은 `docs/PROJECT.md` 뷰포트의 "디바이스 전환 폭"을 따른다. 코드 토큰에 브레이크포인트가 있으면 그것이 먼저다. 둘 다 없으면 멈추고 질문한다. (`docs/questions/design.md`)
- 전환 폭은 코드의 **한 곳**(공통 스타일)에서만 정의하고 모든 컴포넌트가 그것을 가져다 쓴다. 미디어 쿼리 안에서는 CSS 변수를 쓸 수 없으므로 스타일링 방식에 맞는 방법을 쓴다. 예) SCSS 변수·mixin, PostCSS custom media. 컴포넌트마다 숫자를 다시 적지 않는다.

### 6-2. 뷰포트 (화면 폭)
> 기준 값(디바이스·디자인 프레임 크기·구현 기준 폭·최소 폭)은 `docs/PROJECT.md` "뷰포트" 표에 있다.
- IMPORTANT: **가로 폭만 유동**이다. 화면 바깥 폭은 뷰포트 폭을 따르고, 여백·간격·글자 크기·아이콘 크기·반경·요소 높이는 Figma 값(토큰) 그대로 둔다.
- 디자인 프레임 폭(예: 402px)을 화면이나 영역의 width 고정값으로 옮기지 않는다.
- Figma에서 Fill(남은 폭 채우기)인 요소는 폭이 늘고 준다. 프레임 폭에 맞춰 Fixed로 잡힌 전체 너비 요소(예: 좌우 여백을 뺀 버튼)도 유동으로 옮긴다. 그 밖의 Fixed 폭 요소(아이콘, 배지 등)는 그대로 둔다.
- 화면 전체를 비율로 줄이거나 늘리지 않는다. (`transform: scale`, `zoom`, 글자 크기·간격에 `vw` 단위 금지)
- 세로: 프레임 높이는 참고용이다. 내용만큼 늘어나고 넘치면 스크롤한다. 하단 고정 영역(버튼 등)은 Figma에서 고정일 때만 고정한다.
- 폭이 줄어 생기는 줄바꿈·말줄임·넘침은 Figma나 화면 명세에 정한 방법이 없으면 지어내지 않고 질문한다. (`docs/questions/design.md`)
- 최소 폭에서 가로 스크롤이 생기거나 요소가 겹치면 안 된다. 생기면 원인을 보고하고 처리 방법을 묻는다.
- 화면 프레임 폭이 표의 디자인 프레임 크기와 다르면 멈추고 질문한다. (`design.md`, 차단 "예")
- 디바이스가 여럿인 화면은 디바이스마다 Figma 프레임을 따로 확인한다. 한 디바이스 프레임만 있으면 나머지를 지어내지 않고 질문한다.

### 6-3. 선(stroke)
Figma 선은 위치(안쪽·가운데·바깥)에 따라 박스 크기에 들어가는 방식이 CSS 테두리와 다르다. 그대로 `border`를 더하면 선 두께만큼 요소가 커지고, 아래 요소가 밀리며 화면마다 쌓인다.
- Figma 선 위치를 확인한다. (`get_design_context`·`get_metadata`의 stroke 정보)
- **안쪽 선**(Figma 기본): 박스 크기는 Figma 크기 그대로여야 한다. 다음 중 하나로 맞춘다.
  - `box-sizing: border-box` + 높이·폭 고정 (크기가 정해진 요소)
  - 안쪽 여백에서 선 두께를 뺀다 (내용만큼 커지는 요소). 예) 여백 16, 선 1 → `padding: calc(var(--space-16) - var(--border-1))`
  - 실선 한 겹이면 `box-shadow: inset 0 0 0 <두께> <색>`도 된다. 점선·이중선은 안 된다
- **가운데 선**: 선 두께의 절반이 박스 밖으로 나간다. 바깥 절반을 크기에 넣지 않는다.
- **바깥 선**: 박스 크기는 그대로, 선은 `outline` 또는 `box-shadow`(inset 아님)로 그린다.
- 프로젝트가 정한 방식은 9번 예외 "선 옮기는 방식"에 적고 모든 컴포넌트가 같은 방식을 쓴다.

## 7. 금지 사항
- 하드코딩된 색상·간격·폰트 크기 (토큰이 없는 종류의 숫자는 레이아웃 값 파일에만 — 3-4)
- 토큰 없는 그림자·반경·투명도
- 인라인 스타일로 디자인 값 지정
- 화면 전용 스타일 파일, 승인받지 않은 `global.css` 예외 (`docs/ARCHITECTURE.md` 8번)
- Figma에 없는 장식 요소 추가

## 8. 디자인 시스템에 없는 경우
토큰·컴포넌트·변형·아이콘이 없거나, 화면에 직접 그린 요소를 컴포넌트로 만들어야 할 때. (토큰 **종류** 자체가 없는 폭·높이·z-index 등은 3-4)
1. 작업을 멈추고 무엇이 없는지 사용자에게 알린다.
2. DS 변경 요청을 만든다. (`docs/ds-requests/`, 양식 `templates/ds-request.md`) 선택지(디자인 시스템에 추가 / 기존 요소로 대체 / 필요 없음)를 적는다.
3. 결정(반영·대체·기각)은 사용자나 디자이너에게서 받아 요청 파일에 적는다. "기존 요소로 대체"도 요청 파일에 남긴다. 결정 전에는 관련 화면의 명세 확정·퍼블을 시작하지 않는다. 사용자가 허락하면 가정으로 진행할 수 있다. (`docs/ds-requests/_index.md` 2번 "가정 진행") 가정 값의 숫자는 레이아웃 값 파일에 `--assume-*`로 둔다. (3-4)
- Figma 디자인이 무엇을 뜻하는지만 확인하면 되는 것은 요청이 아니라 질문(`docs/questions/design.md`)이다. 구분은 `docs/ds-requests/_index.md` 1번.
