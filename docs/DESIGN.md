# DESIGN.md — 디자인 시스템 사용 규칙

> 이 문서는 프로젝트와 무관하게 재사용하는 **규칙과 이유**만 담는다.
> 토큰 값·컴포넌트 목록 같은 **수치와 목록은 적지 않는다.** Figma가 원본이며 MCP로 조회한다.
> Figma 라이브러리 URL과 코드 토큰 위치는 `docs/PROJECT.md`를 따른다.

## 1. 원본(Source of Truth)
- 값의 원본은 Figma다. 이 문서나 다른 md에 값을 복사해 두지 않는다. (복사하면 Figma와 어긋난다)
- 코드의 토큰 파일은 Figma 변수를 옮긴 결과물이다. 둘이 다르면 Figma를 기준으로 하고 사용자에게 알린다.
- IMPORTANT: 코드 토큰 파일(`tokens.css`, `tokens.ts`)은 `token-sync` 스킬로만 만든다. 손으로 고치지 않는다. (다음 동기화 때 사라진다)

## 2. 값 조회 방법 (Figma MCP)
| 필요한 정보 | 조회 방법 |
|---|---|
| 화면 구조·스타일 | 화면 명세의 Figma 노드 → `get_design_context` |
| 화면에 쓰인 변수의 최종 값 | `get_variable_defs` |
| 변수 전체 (컬렉션·모드·별칭) | `token-sync` 스킬 (`use_figma` 읽기 전용) |
| 기존 컴포넌트·스타일 검색 | `search_design_system` |
| 컴포넌트 ↔ 코드 매핑 | `get_code_connect_map` |
| 시각 비교 | `get_screenshot` |

- IMPORTANT: 필요한 노드만 조회한다. 페이지·파일 전체를 조회하지 않는다. (토큰 절감)
- 같은 작업 안에서 이미 조회한 값은 다시 조회하지 않는다.

## 3. 토큰 규칙

### 3-1. 사용
- IMPORTANT: 색상·간격·폰트·반경·그림자는 코드 토큰으로만 쓴다. 숫자·HEX 직접 입력 금지.
- 의미 토큰(semantic, 예: `color.text.primary`)을 우선 쓴다. 원시 토큰(primitive, 예: `blue.500`)은 의미 토큰이 없을 때만 쓴다.
- Figma 변수명과 코드 토큰명은 3-2 이름 규칙으로 대응시켜 찾는다. 대응하는 토큰이 없으면 임의로 만들지 않고 묻는다.
- Figma 변수에는 있는데 코드 토큰 파일에 없으면 토큰 파일이 오래된 것이다. 토큰 파일을 고치지 않고 `token-sync`를 안내한다.
- 비슷한 값이 있다고 다른 용도의 토큰을 빌려 쓰지 않는다. (예: 에러 색을 경고에 사용 금지)

### 3-2. Figma 변수 → 코드 토큰 변환
> `token-sync` 스킬이 이 규칙대로 토큰 파일을 만든다. 같은 Figma 변수는 언제 변환해도 같은 결과가 나와야 한다.

**대상**
- `docs/PROJECT.md` "Figma 변수 파일"의 로컬 변수 전체
- 제외: 게시에서 숨긴 컬렉션·변수, 불리언 변수, 9번에 적은 제외 컬렉션

**이름**
| Figma 변수 | CSS 변수 | TS 참조 |
|---|---|---|
| `color/text/primary` | `--color-text-primary` | `tokens.color.text.primary` |
| `color/bg subtle` | `--color-bg-subtle` | `tokens.color.bgSubtle` |
| `blue/500` | `--blue-500` | `tokens.blue['500']` |
| `spacing/0.5` | `--spacing-0_5` | `tokens.spacing['0_5']` |

- 소문자로 바꾸고, `/`와 공백은 `-`, `.`은 `_`로 바꾼다. 그 밖의 특수문자는 지운다.
- 컬렉션 이름은 넣지 않는다.
- TS는 `/`로 나눈 단계를 객체 단계로 쓴다. 단계 안의 `-`는 camelCase로 바꾸고, 숫자로 시작하는 단계는 문자열 키로 쓴다.
- 변환한 이름이 겹치거나, 한 이름이 값이면서 하위 단계를 가지면 변환하지 않고 멈춘다. (Figma 이름을 정리해야 한다)

**값**
| 변수 종류 | 출력 |
|---|---|
| 색상 | 소문자 `#rrggbb`, 투명도가 있으면 `#rrggbbaa` |
| 숫자 — 간격·반경·크기·글자 크기·행간·자간·선 두께 | `px` (9번에서 rem으로 바꿀 수 있음) |
| 숫자 — 글자 굵기·불투명도 등 단위 없는 값 | 숫자 그대로. 불투명도가 0~100 값이면 100으로 나눈다 |
| 문자열 — 글꼴 | 따옴표로 감싼다. 대체 글꼴은 9번에 적는다 |
| 문자열 — 글자 굵기 이름 | Thin 100 · ExtraLight 200 · Light 300 · Regular 400 · Medium 500 · SemiBold 600 · Bold 700 · ExtraBold 800 · Black 900 (띄어쓰기 무시). 그 밖의 이름은 묻는다 |

- 숫자 종류는 변수의 적용 범위(scopes)로 판단한다. 적용 범위가 "모든 범위"면 이름 첫 단계(`spacing`, `radius`, `size`, `font-size`, `line-height` 등)로 판단하고, 그래도 모르면 멈추고 묻는다.

**별칭**
- 다른 변수를 가리키는 값은 `var(--대상)`으로 쓴다. 최종 값으로 풀어 쓰지 않는다.
- 대상이 동기화 범위 밖(다른 파일·라이브러리, 숨긴 변수)이면 멈춘다.

**모드**
- 컬렉션의 기본 모드 값은 `:root`에, 나머지 모드 값은 `[data-theme="<모드 이름>"]` 블록에 쓴다. 모드 이름도 이름 규칙으로 바꾼다. (예: `Dark` → `dark`)
- 기본 모드와 값이 같은 변수는 모드 블록에 다시 쓰지 않는다.
- 모드가 2개 이상인 컬렉션이 둘 이상이면 9번에 컬렉션별 속성 이름을 정한 뒤 진행한다.
- TS 참조는 `var()` 문자열이므로 모드와 관계없이 하나다.

**순서·파일**
- 순서: 원시 토큰(모든 모드 값이 직접 값) → 의미 토큰(별칭 값이 하나라도 있음). 각각 이름순.
- `tokens.css`: CSS 변수 정의 / `tokens.ts`: 같은 토큰의 `var()` 참조 객체 (`as const`)
- 두 파일 맨 위에 자동 생성 표시를 넣는다.

```css
/* 자동 생성 — 직접 고치지 마세요. token-sync 스킬로 갱신합니다. */
:root {
  --blue-500: #2563eb;
  --gray-50: #f9fafb;
  --gray-900: #111827;
  --spacing-4: 16px;
  --color-text-primary: var(--gray-900);
}

[data-theme="dark"] {
  --color-text-primary: var(--gray-50);
}
```

```ts
// 자동 생성 — 직접 고치지 마세요. token-sync 스킬로 갱신합니다.
export const tokens = {
  blue: { '500': 'var(--blue-500)' },
  gray: { '50': 'var(--gray-50)', '900': 'var(--gray-900)' },
  spacing: { '4': 'var(--spacing-4)' },
  color: { text: { primary: 'var(--color-text-primary)' } },
} as const;
```

## 4. 컴포넌트 사용 규칙
- IMPORTANT: 순서는 ① Code Connect 매핑 확인 → ② 코드에서 기존 컴포넌트 검색 → ③ 없을 때만 새로 만든다.
- 기존 컴포넌트를 복사해 변형하지 않는다. 필요한 변형은 props/variant로 확장하고, 확장이 어려우면 묻는다.
- 새 컴포넌트는 `templates/component-spec.md`로 명세를 먼저 쓰고 승인받는다.
- Figma 컴포넌트명과 코드 컴포넌트명을 일치시킨다.

## 5. 상태 규칙
- 모든 화면·컴포넌트는 해당하는 상태를 빠짐없이 구현한다: 기본 / 로딩 / 빈 값 / 에러 / 비활성 / (해당 시) 점검.
- Figma에 상태 디자인이 없으면 임의로 만들지 않고 화면 명세에 "디자인 필요"로 표시한 뒤 묻는다.

## 6. 레이아웃 규칙
- 간격은 간격 토큰 단위로만 맞춘다. 눈대중으로 맞춘 값은 쓰지 않는다.
- Figma 오토레이아웃은 flex/grid로 옮긴다. 절대 위치는 Figma에서도 절대 위치일 때만 쓴다.
- 반응형 기준(브레이크포인트)은 코드 토큰을 따른다.

## 7. 금지 사항
- 하드코딩된 색상·간격·폰트 크기
- 토큰 없는 그림자·반경·투명도
- 인라인 스타일로 디자인 값 지정
- Figma에 없는 장식 요소 추가

## 8. 디자인 시스템에 없는 경우
1. 작업을 멈추고 무엇이 없는지 사용자에게 알린다.
2. 선택지(기존 요소로 대체 / 새로 추가 / 디자이너 확인)를 제시하고 결정을 받는다.
3. 결정은 `templates/adr.md` 양식으로 `docs/decisions/`에 남긴다.
