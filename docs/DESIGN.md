# DESIGN.md — 디자인 시스템 사용 규칙

> 이 문서는 프로젝트와 무관하게 재사용하는 **규칙과 이유**만 담는다.
> 토큰 값·컴포넌트 목록 같은 **수치와 목록은 적지 않는다.** Figma가 원본이며 MCP로 조회한다.
> Figma 라이브러리 URL과 코드 토큰 위치는 `docs/PROJECT.md`를 따른다.

## 1. 원본(Source of Truth)
- 값의 원본은 Figma다. 이 문서나 다른 md에 값을 복사해 두지 않는다. (복사하면 Figma와 어긋난다)
- 코드의 토큰 파일은 Figma 변수를 옮긴 결과물이다. 둘이 다르면 Figma를 기준으로 하고 사용자에게 알린다.

## 2. 값 조회 방법 (Figma MCP)
| 필요한 정보 | 조회 방법 |
|---|---|
| 화면 구조·스타일 | 화면 명세의 Figma 노드 → `get_design_context` |
| 색상·간격·타이포 변수 | `get_variable_defs` |
| 기존 컴포넌트·스타일 검색 | `search_design_system` |
| 컴포넌트 ↔ 코드 매핑 | `get_code_connect_map` |
| 시각 비교 | `get_screenshot` |

- IMPORTANT: 필요한 노드만 조회한다. 페이지·파일 전체를 조회하지 않는다. (토큰 절감)
- 같은 작업 안에서 이미 조회한 값은 다시 조회하지 않는다.

## 3. 토큰 사용 규칙
- IMPORTANT: 색상·간격·폰트·반경·그림자는 코드 토큰으로만 쓴다. 숫자·HEX 직접 입력 금지.
- 의미 토큰(semantic, 예: `color.text.primary`)을 우선 쓴다. 원시 토큰(primitive, 예: `blue.500`)은 의미 토큰이 없을 때만 쓴다.
- Figma 변수명과 코드 토큰명이 다르면 이름 변환 규칙에 따라 찾는다. 대응하는 토큰이 없으면 임의로 만들지 않고 묻는다.
- 비슷한 값이 있다고 다른 용도의 토큰을 빌려 쓰지 않는다. (예: 에러 색을 경고에 사용 금지)

## 4. 컴포넌트 사용 규칙
- IMPORTANT: 순서는 ① Code Connect 매핑 확인 → ② 코드에서 기존 컴포넌트 검색 → ③ 없을 때만 새로 만든다.
- 기존 컴포넌트를 복사해 변형하지 않는다. 필요한 변형은 props/variant로 확장하고, 확장이 어려우면 묻는다.
- 새 컴포넌트는 `templates/component-spec.md`로 명세를 먼저 쓰고 승인받는다.
- Figma 컴포넌트명과 코드 컴포넌트명을 일치시킨다.

## 5. 상태 규칙
- 모든 화면·컴포넌트는 해당하는 상태를 빠짐없이 구현한다: 기본 / 로딩 / 빈 값 / 에러 / 비활성 / (해당 시) 점검.
- Figma에 상태 디자인이 없으면 임의로 만들지 않고 화면 명세에 "디자인 필요"로 표시한 뒤 묻는다.

## 6. 레이아웃 규칙
- 간격은 간격 토큰 단위로만 맞춘다. 눈대중으로 맞춘 값은 쓰지 않는다.
- Figma 오토레이아웃은 flex/grid로 옮긴다. 절대 위치는 Figma에서도 절대 위치일 때만 쓴다.
- 반응형 기준(브레이크포인트)은 코드 토큰을 따른다.

## 7. 금지 사항
- 하드코딩된 색상·간격·폰트 크기
- 토큰 없는 그림자·반경·투명도
- 인라인 스타일로 디자인 값 지정
- Figma에 없는 장식 요소 추가

## 8. 디자인 시스템에 없는 경우
1. 작업을 멈추고 무엇이 없는지 사용자에게 알린다.
2. 선택지(기존 요소로 대체 / 새로 추가 / 디자이너 확인)를 제시하고 결정을 받는다.
3. 결정은 `docs/decisions/`에 ADR로 남긴다.
