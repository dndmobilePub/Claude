# QA.md — 검수 기준

> 퍼블 결과가 화면 명세·Figma와 맞는지 확인하는 기준이다. `implement-screen` 6~8단계와 `design-system-reviewer`가 이 문서를 따른다.
> 결과는 화면마다 `docs/reports/<화면ID>.md` 한 파일에 남긴다. 양식: `templates/report.md`
> 화면별로 더 확인할 것은 화면 명세 9번 "완료 기준"에 적는다. 여기에는 모든 화면에 공통인 기준만 둔다.

## 1. 검수 순서
| 순서 | 누가 | 무엇을 | 기준 |
|---|---|---|---|
| 1 | AI (퍼블한 대화) | 린트·테스트 | `docs/PROJECT.md` 명령어 ("없음"이면 건너뛰고 기록) |
| 2 | AI | 디자인 시스템 위반 | `ds-check` 스킬 |
| 3 | AI | 시각 비교 | 이 문서 3번 |
| 4 | AI | 폭·상태 확인 | `docs/DESIGN.md` 6-2, 화면 명세 3번 |
| 5 | AI | 공통 체크리스트 + 화면별 완료 기준 | 이 문서 2번, 화면 명세 9번 |
| 6 | 리뷰어 에이전트 | 독립 검토 (규모가 크거나 신규 컴포넌트가 있을 때) | `design-system-reviewer` |
| 7 | 사람 | 보고 파일과 화면 확인 → 승인 | PR 리뷰 (`docs/GIT.md` 6번) |

- 문제가 나오면 고친 뒤 그 단계부터 다시 한다.
- 결과는 단계마다 대화에 길게 적지 않고 보고 파일에 모은다.

## 3. 시각 비교
### 3-1. 비교 대상
- 화면 명세 3번 상태 표의 Figma 노드마다 하나씩 비교한다. "디자인 필요" 상태는 비교하지 않고 보고 파일에 남은 작업으로 적는다.
- 디바이스가 여럿이면 디바이스마다 비교한다. (`docs/PROJECT.md` "뷰포트")

### 3-2. 방법
- Figma 쪽: `get_screenshot`으로 그 상태 노드를 받는다.
- 퍼블 쪽: 화면을 **디자인 프레임 폭**으로 열고(`ARCHITECTURE.md` 11번 "화면 하나를 따로 여는 방법"), 같은 상태로 바꾼 뒤 캡처한다. 캡처 방법은 5번 예외를 따른다. 정해져 있지 않으면 사람에게 캡처 이미지를 요청한다.
- 둘을 나란히 보고 영역별(머리·본문·하단 고정 등)로 차이를 찾는다.
- 구현 기준 폭·최소 폭은 Figma와 비교하지 않고 깨짐만 확인한다. (C10)
- 캡처를 받을 수 없어 비교하지 못하면 "확인 못 함"과 이유를 적는다. 이때 결과는 "통과"가 될 수 없다. (4번)

### 3-3. 허용 차이
- 위치·크기: 5번 예외의 값까지 허용한다. 기본은 ±2px.
- 색: 픽셀 색 값이 아니라 쓴 토큰이 Figma 변수와 같은지로 판단한다.
- 글꼴: 같은 글꼴·크기·굵기·줄 높이 토큰이면 브라우저 렌더링 차이는 허용한다.
- 아이콘·이미지: 같은 에셋이어야 한다.
- 허용 차이 안의 차이는 기록하지 않는다.

### 3-4. 차이 원인 분류
| 분류 | 예 | 처리 |
|---|---|---|
| 구현 오류 | 간격 토큰 잘못 씀, 요소 빠짐 | 고치고 다시 비교 |
| 토큰·컴포넌트 차이 | 대응 토큰이 없음, 공통 컴포넌트 모양이 Figma와 다름 | `DESIGN.md` 8번 절차 |
| Figma 쪽 문제 | 화면끼리 같은 요소가 다름, 상태 프레임과 기본 프레임이 다름 | `docs/questions/design.md`에 질문 |
| 렌더링 차이 | 글꼴 안티앨리어싱, 줄바꿈 위치의 미세한 차이 | 허용. 기록만 |
| 폭 유동 | 디자인 프레임 폭이 아닌 폭에서 늘어나고 줄어든 결과 | 허용 (`DESIGN.md` 6-2) |

## 4. 결과
보고 파일 frontmatter `result`에 적는다. 화면 상태는 늘리지 않는다. (화면 상태는 "구현완료"까지)

| 결과 | 조건 | 다음 |
|---|---|---|
| 통과 | 공통 체크리스트·화면별 완료 기준을 모두 충족. 남은 차이는 렌더링 차이·폭 유동뿐 | 사용자 승인 후 "구현완료" |
| 조건부 통과 | 미충족 항목은 없지만 가정 값을 씀, "디자인 필요" 상태가 남음, 원인이 "Figma 쪽 문제"인 차이가 질문으로 열려 있음, 또는 시각 비교를 하지 못한 상태가 있음 | 남은 것을 보고하고, 사용자가 승인하면 "구현완료" |
| 미통과 | 미충족 항목이 있음, 또는 구현 오류·토큰·컴포넌트 차이가 남음 | "구현완료"로 바꾸지 않는다. 고친 뒤 다시 검수 |

- 조건부 통과로 구현완료가 된 화면은 남은 질문이 확정되면 그 부분만 고쳐 다시 검수한다. (5번 재검수 범위와 같다)

## 5. 다시 검수할 때
버전 변경(`version-update`)이나 질문 확정으로 이미 퍼블한 화면을 고친 경우.
- 공통 체크리스트(2번)는 **전체**를 다시 확인한다.
- 시각 비교(3번)는 **바뀐 상태 프레임만** 다시 한다. 바뀐 범위는 변경 기록(`docs/changes/`)의 이 화면 줄이나 확정된 질문으로 정한다.
- 보고 파일은 새로 덮어쓴다. 다시 비교하지 않은 줄은 이전 결과를 옮기고 처리 칸에 "이전 검수 유지"라고 적는다. frontmatter `scope`에 재검수 근거를 적는다.
