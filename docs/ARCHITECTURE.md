# ARCHITECTURE.md — 퍼블 파일 구조 규칙

> 결과물은 **개발팀에 넘기는 퍼블리싱 파일**이다. 이 문서는 퍼블 파일을 어디에 어떻게 두는지, 퍼블과 개발의 경계를 정한다.
> 퍼블 언어(JS / React / Vue)와 스타일링 방식은 `docs/PROJECT.md`, 실제 경로는 맨 아래 예외 섹션을 따른다.
> 컴포넌트 폴더 규칙은 `src/components/AGENTS.md`, 디자인 값 규칙은 `docs/DESIGN.md`를 따른다.

## 1. 퍼블과 개발의 경계
| 구분 | 퍼블이 하는 일 | 개발에 넘기는 일 (퍼블에서 하지 않음) |
|---|---|---|
| 화면 | 마크업, 스타일, 컴포넌트 조립 | — |
| 상태 | 기본·로딩·빈 값·에러·비활성·점검 화면을 만들고 바꿔 볼 수 있게 함 (6번) | 어떤 상태를 언제 보여줄지 결정하는 로직 |
| 화면 안 동작 | 탭·아코디언·토글, 팝업 열고 닫기, 입력 중 금액 쉼표 표시, 버튼 활성·비활성 표시 | 서버 호출, 인증, 세션 처리 |
| 화면 사이 이동 | 이동할 곳을 표시만 함 (4번) | 라우팅, 화면 사이 데이터 전달 |
| 데이터 | 더미 데이터로 화면을 채움 (5번) | 실제 데이터 연결 |
| 입력 검증 | 에러 표시 상태와 문구 | 검증 실행 (규칙 원본은 화면 명세 6번) |

- IMPORTANT: 개발 몫의 일을 퍼블에서 임의로 구현하지 않는다. 필요해 보이면 묻는다.
- IMPORTANT: 문자열을 HTML로 바로 넣지 않는다. (`innerHTML`·`outerHTML`·`insertAdjacentHTML`·`document.write`, React `dangerouslySetInnerHTML`, Vue `v-html`) 내용은 텍스트로 넣거나 마크업으로 만든다. 꼭 필요하면 묻는다.
- IMPORTANT: 외부 스크립트(`<script src="https://...">`, CDN)나 새 패키지를 임의로 추가하지 않는다. 필요하면 이유와 함께 묻는다. (`docs/PROJECT.md` "기타 주요 라이브러리")
- 개발이 그대로 가져다 쓰도록 만든다. 화면은 조립만 하고 스타일을 갖지 않는다. 반복되는 것은 컴포넌트·공통으로 옮긴다. (스타일은 8번)

## 2. 계층과 책임
| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 화면 | 컴포넌트 조립, 화면 안 동작, 상태별 표시 | 화면 전용 스타일, 디자인 값 직접 입력, 금액·마스킹 직접 구현, 화면 이동 |
| 컴포넌트 | `src/components/AGENTS.md` 참조 | 데이터 가져오기 |
| 더미 데이터 | 화면을 채울 가짜 값 (5번) | UI |
| 공통 | 금액·마스킹 표시 포맷, 날짜 표시 같은 유틸 | 화면별 업무 규칙 |
| 스타일 | 토큰(`token-sync` 생성), 공통 스타일, 예외 스타일(`global.css`, 8번) | 화면별 스타일 파일 |

- 가져오는 방향은 한쪽만: 화면 → 컴포넌트·더미 데이터·공통·스타일.
- IMPORTANT: 화면끼리 서로 가져오지 않는다. 여러 화면이 쓰는 것은 조합 컴포넌트나 공통으로 옮긴다.

## 3. 폴더 구조
- `docs/PROJECT.md` "파일 구조"에 따라 3-1 또는 3-2를 쓴다. 비어 있으면 3-1이다.
- `src/`는 `docs/PROJECT.md` "퍼블 소스 폴더"의 기본값이다. 다른 폴더를 쓰면 이 문서와 다른 지침의 `src/`를 그 폴더로 읽는다. 바꿀 때 손으로 맞출 곳은 `docs/HARNESS.md` 5번.
- 저장소 루트는 퍼블 소스 폴더로 쓰지 않는다. 지침 파일(`docs/`·`.claude/`)과 섞여 점검·규칙이 엉뚱한 파일에 걸린다. 루트에 `html/`·`css/`를 두던 프로젝트도 폴더 하나(예: `pub/`) 아래에 둔다.
- 공통 유틸(`lib/`)은 만들거나 고칠 때 단위 테스트를 함께 만든다. 테스트 파일은 유틸 옆에 `<이름>.test.<확장자>`로 둔다. 실행은 `docs/PROJECT.md` "린트/테스트" 명령을 따르고, 테스트 도구가 없는 프로젝트는 Node 내장 테스트(`node --test`, 패키지 설치 없음)로 돌린다. 업종별 필수 테스트 항목은 해당 규칙 문서(`.claude/rules/`)에 있다.
- `<도메인>` 폴더 이름은 플로우 문서 파일 이름과 같게 한다. (예: `ui-flow/transfer.md` → `screens/transfer/`, `html/transfer/`)

### 3-1. 화면 폴더 (기본. JS·React·Vue)
화면마다 폴더 하나에 그 화면 파일을 모은다.
```
src/
  screens/<도메인>/<화면ID>-<이름>/   # 화면 (스타일 파일은 두지 않는다 — 8번)
  components/                       # 컴포넌트 (스타일은 컴포넌트 안에)
  dummy/<도메인>.<확장자>             # 더미 데이터 (5번)
  lib/                              # 공통 유틸 (단위 테스트를 함께 둔다)
  styles/                           # 토큰·공통 스타일·global.css(예외)
```
- 스토리북을 쓰면 스토리 파일 위치는 `src/components/AGENTS.md` 예외 섹션을 따른다.
- 언어별 화면 폴더 안 파일은 9번 예시를 따른다.

### 3-2. 종류별 폴더 (JS(HTML·CSS·JS)만)
파일을 종류(HTML·CSS·JS·이미지)별 폴더에 나눠 둔다. 정적 퍼블에서 흔한 구조다. React·Vue는 3-1만 쓴다.
```
src/
  html/<도메인>/<화면ID>.html         # 화면 (파일 이름이 화면 ID)
  html/components/<이름>.html         # 컴포넌트 마크업 견본
  css/tokens/                         # 토큰 (token-sync 생성)
  css/common.css                      # 공통 스타일
  css/components/<이름>.css            # 컴포넌트 스타일
  css/global.css                      # 예외 스타일 (8번)
  js/components/<이름>.js              # 컴포넌트 동작 (탭·아코디언 등, 있을 때만)
  js/<도메인>/<화면ID>.js              # 화면 전용 동작 (있을 때만)
  js/lib/                             # 공통 유틸 (3번 lib/ 규칙과 같다)
  images/
```
- 화면 전용 CSS 파일은 두지 않는다. (8번)
- 코드 토큰 위치를 따로 적지 않으면 `<퍼블 소스 폴더>/css/tokens/`로 본다.
- 화면끼리 가져오지 않는 규칙: 화면 전용 JS는 다른 화면의 JS를 불러오지 않는다. 여러 화면이 쓰는 동작은 `js/components/`나 `js/lib/`로 옮긴다.
- 더미 데이터는 5번대로 마크업에 직접 쓴다. 따로 폴더가 없다.
- 폴더 이름이 다르거나, 머리말·꼬리말 같은 공통 조각을 넣는 방법은 11번 예외에 정한다.

## 4. 화면 위치와 이동 표시
- 화면 ID로 바로 찾을 수 있게 한다.
  - 3-1: 폴더 이름 `<화면ID>-<PascalCase 이름>` (예: `TRF-010-AmountInput`)
  - 3-2: 파일 이름 `<화면ID>.html`, 화면 전용 JS도 `<화면ID>.js` (예: `html/transfer/TRF-010.html`)
- 화면 바깥 요소의 `data-screen="<화면ID>"`
  - 3-2: 모든 화면에 붙인다.
  - 3-1: `global.css` 예외가 있는 화면에만 붙인다. (8-1)
- 화면 하나는 따로 열어 확인할 수 있어야 한다. 확인 방법은 언어마다 달라서 11번 예외에 정한다.
- IMPORTANT: 화면 사이 이동은 구현하지 않는다. 다른 화면으로 가는 링크·버튼에는 이동할 화면 ID를 `data-screen-link="<화면ID>"` 속성으로 표시한다.
  - 개발이 이동 위치를 검색으로 찾게 하기 위해서다. 조건에 따라 가는 곳이 다르면 화면 명세 4번에 적고, 속성에는 대표 이동 화면만 적는다.
- 화면 전용 조각(3-1은 화면 폴더 안, 3-2는 화면 HTML 안 마크업)이 두 화면 이상에서 쓰이면 조합 컴포넌트로 옮긴다.

## 5. 더미 데이터
- React·Vue: 화면은 `dummy/<도메인>`의 값을 가져와 컴포넌트에 넘긴다. 화면·컴포넌트 안에 값을 직접 쓰지 않는다.
- JS(HTML·CSS·JS): 더미 값을 마크업에 직접 쓴다. 값이 들어간 요소에는 화면 명세 5번의 필드 이름을 `data-field="<필드명>"`으로 표시한다.
- 공통
  - 필드 이름은 화면 명세 5번 "표시 데이터" 표를 따른다. 개발이 같은 이름으로 실제 데이터를 연결하기 위해서다.
  - 실제 개인정보·계좌번호를 쓰지 않는다. 가짜임이 드러나는 값을 쓴다.
  - 상태 확인에 필요한 값(빈 목록, 긴 이름, 큰 금액 등)도 함께 준비한다.
  - 금액·계좌번호는 원본 값으로 두고 표시는 공통 유틸로 포맷한다. (`finance-ui.md` 1·3번)

## 6. 상태 확인
- 화면 명세 3번의 상태를 모두 만든다. 화면 하나에서 상태를 바꿔 볼 수 있게 한다.
- 바꾸는 방법(확인용 선택 상자, 주소 뒤 매개변수, 스토리 등)은 11번 예외에 정하고 모든 화면에 같게 쓴다.
- 확인용 장치는 개발이 쉽게 걷어낼 수 있게 한 곳에 모은다. 화면 코드 곳곳에 흩어 넣지 않는다.

## 7. 화면 안 동작
- 1번 표의 "퍼블이 하는 일"만 구현한다.
- 버튼 중복 클릭 방지, 요청 중 로딩 표시처럼 서버 응답이 필요한 동작은 상태(로딩·비활성) 화면까지만 만든다. (`finance-ui.md` 5번)
- IMPORTANT: 민감 정보를 브라우저 저장소(localStorage·sessionStorage)나 URL에 두지 않는다. (`finance-ui.md` 4번)

## 8. 스타일
- 디자인 값은 토큰만 쓴다. (`docs/DESIGN.md` 3번) 작성 방식은 `docs/PROJECT.md`의 스타일링을 따른다.
- IMPORTANT: 스타일은 컴포넌트 안에서 해결한다. 화면 전용 스타일 파일을 만들지 않는다. (React 화면의 CSS Modules, Vue 화면 컴포넌트의 `<style>`, 3-2의 화면별 CSS 파일도 같다)
- 화면 안 배치(영역 사이 간격·정렬)도 레이아웃 컴포넌트나 공통 레이아웃 스타일로 한다.
- 스타일을 두는 곳

  | 무엇 | 어디에 |
  |---|---|
  | 컴포넌트 모양·변형·상태 | 컴포넌트 안 (파일 구성은 `src/components/AGENTS.md` 예외 섹션) |
  | 여러 컴포넌트가 함께 쓰는 것 (기본 글꼴·바탕, 레이아웃 공통) | 공통 스타일 (3-1 `styles/`, 3-2 `css/common.css`) |
  | 컴포넌트·공통으로 정말 해결할 수 없는 한 화면의 차이 | 예외 스타일 `global.css` (3-1 `styles/global.css`, 3-2 `css/global.css`) — 8-1 |

### 8-1. 예외 스타일 (`global.css`)
- 극히 드문 경우에만 쓴다. 대부분은 공통으로 해결한다.
- IMPORTANT: 넣기 전에 순서대로 확인한다.
  1. 컴포넌트 변형·속성으로 해결한다. 맞는 변형이 없으면 컴포넌트에 변형을 추가한다. (`docs/DESIGN.md` 4번, 컴포넌트 명세 승인)
  2. 공통 스타일로 해결한다.
  3. 그래도 안 되면 이유와 함께 묻고, 승인받은 경우에만 넣는다.
- 디자인 시스템에 없는 값(토큰·변형)이 필요해서라면 예외로 넣지 않고 DS 변경 요청을 만든다. (`docs/DESIGN.md` 8번)
- 쓰는 법
  - 그 화면에만 걸리게 `[data-screen="<화면ID>"]` 선택자 아래에 쓴다. 화면 바깥 요소에 같은 속성을 붙인다. (4번)
  - 바로 위에 `/* 예외: <화면ID> — <이유> */` 주석을 단다.
  - 예외라도 값은 토큰만 쓴다. `!important`로 컴포넌트 스타일을 덮지 않는다. 꼭 필요하면 주석 이유에 적는다.
- 같은 예외가 두 화면 이상에 생기면 예외가 아니다. 컴포넌트 변형이나 공통 스타일로 옮긴다.
- 넣은 예외는 검수 보고 "개발 전달"에 적는다. (10번)
- 형식은 `check-pub`의 P7이 점검한다. (화면 전용 스타일 파일, `data-screen` 범위, 이유 주석)

예)
```css
/* 예외: TRF-010 — 안내 배너가 키패드에 가리지 않게 아래 여백을 더 줌 (Q-DS-004) */
[data-screen="TRF-010"] .notice-banner {
  margin-bottom: var(--space-24);
}
```

## 9. 언어별 예시
### JS (HTML·CSS·JS) — 화면 폴더 (3-1)
```
src/screens/transfer/TRF-010-AmountInput/index.html
src/screens/transfer/TRF-010-AmountInput/script.js    # 화면 안 동작이 있을 때만
```

### JS (HTML·CSS·JS) — 종류별 폴더 (3-2)
```
src/html/transfer/TRF-010.html                        # <main data-screen="TRF-010">
src/js/transfer/TRF-010.js                            # 화면 전용 동작이 있을 때만
```

### React
```
src/screens/transfer/TRF-010-AmountInput/index.jsx    # TypeScript면 .tsx
src/dummy/transfer.js                                 # TypeScript면 .ts
```

### Vue
```
src/screens/transfer/TRF-010-AmountInput/AmountInputScreen.vue
src/dummy/transfer.js
```
- React·Vue 화면 컴포넌트 이름은 `<이름>Screen`이다. 프로젝트 전체에서 겹치지 않게 도메인을 붙인다. (예: `TransferResultScreen`)

## 10. 개발 전달
- 화면을 넘길 때 검수 보고 파일(`docs/reports/<화면ID>.md` 6번)에 아래를 적는다. 개발이 이어서 할 일을 빠짐없이 알기 위해서다.
  - 더미 데이터 위치와 필드 목록
  - `data-screen-link` 이동 표시 목록
  - 개발 몫으로 남긴 동작 (서버 호출, 검증 실행, 상태 결정 등)
  - 상태 확인 방법
  - `global.css` 예외 목록 (선택자, 이유)
