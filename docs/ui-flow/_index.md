# UI Flow 인덱스

> 플로우는 `write-flow`, 화면 명세는 `write-screen-spec` 스킬로 작성한다. (양식: `templates/flow.md`, `templates/screen-spec.md`)
> 맨 아래 "현황"은 `build-index` 훅이 자동 생성한다. 직접 고치지 말고 원본을 고친다.
> - 화면 ID·화면명 원본: IA 사본 `docs/ia/screen-list.md` (`ia-sync`가 생성). IA가 없는 프로젝트는 각 플로우 문서의 "2. 화면 목록" 표
> - 예정일 원본: IA 사본의 "2. 일정" 표 (`docs/ia/source.md`의 "현황에 표시할 단계")
> - 화면 상태·Figma 원본: 각 화면 명세의 frontmatter
> IMPORTANT: 현황 표는 전체를 읽지 말고 필요한 화면 ID·도메인 행만 검색한다. (토큰 절감)

## 화면 ID 체계
- 형식: `docs/PROJECT.md`의 "화면 ID 형식" (정규식). 이 형식과 맞지 않는 ID는 경고한다.
- IA가 있으면 화면 ID는 IA가 정한다. 지침이 새 ID를 만들지 않는다.
- IA가 없으면 `write-flow`가 형식에 맞춰 제안하고 승인받는다. (번호는 사이에 끼워 넣을 수 있게 간격을 둔다)
- 도메인 키·약어: IA가 있으면 `docs/ia/source.md` 3번, 없으면 각 플로우 frontmatter(`code`)

## 공통 화면
- **공통 화면**: 특정 도메인에 속하지 않고 여러 플로우가 이동해 가는 화면. 화면 전체가 바뀌는 것만 해당한다. (예: 오류 페이지, 서비스 점검, 세션 만료, 네트워크 오류)
  - 팝업·토스트·입력란 에러처럼 화면 안에서 보이는 것은 공통 화면이 아니다. 각 화면 명세 3번 상태와 공통 컴포넌트로 처리한다.
- **위치**: 공통 화면도 도메인 하나로 다룬다. 플로우 문서는 `docs/ui-flow/<공통 화면 도메인 키>.md` (`docs/PROJECT.md`, 기본 `common`). 화면 명세·퍼블·검수는 일반 화면과 같다.
- **공통 플로우 문서**: 2번 화면 목록과 "사용처" 표를 쓴다. 3~8번은 "해당 없음"으로 둘 수 있다.

  | 공통 화면 | 이동해 오는 도메인·상황 | 복귀 지점 |
  |---|---|---|
  | (예: COM-010 서비스 점검) | 전체 도메인, 점검 응답을 받았을 때 | 앱 처음 |

- **화면 ID**
  - IA에 공통 화면이 있으면 IA를 따른다. IA의 도메인 값은 `docs/ia/source.md` 3번에서 공통 화면 도메인 키에 대응시킨다.
  - IA에 없으면 `docs/PROJECT.md` "공통 화면 임시 ID 약어"로 임시 ID를 제안하고 승인받는다. 같은 때 `docs/questions/ia.md`에 IA 추가 요청 질문을 남긴다. (대상 = 임시 ID, 차단 "아니오")
  - 질문이 열려 있는 동안 화면 맵에는 "IA 추가 요청 중"으로 표시된다. 질문이 없으면 훅이 경고한다.
  - IA에 들어오면 IA의 ID로 바꾼다. 다른 ID면 사용처(도메인 플로우 6번, 명세 4번, `src/`의 `data-screen-link`)를 함께 고친다. (`version-update` 또는 `ia-sync` 비교 보고에서 처리)
- **도메인 플로우와 연결**: 도메인 플로우 6번 예외 표의 "처리" 칸에 공통 화면 ID를 적는다. 명세 4번에서 이동 대상으로 적고, 퍼블은 `data-screen-link`로 표시한다.

## 화면 상태 정의
| 상태 | 의미 | 바꾸는 시점 |
|---|---|---|
| 플로우 전 | IA에 있지만 아직 어느 플로우에도 없음 (IA가 있는 프로젝트만) | 자동 표시 (frontmatter에 쓰지 않는다) |
| 명세 전 | 플로우에 등록됐지만 명세 파일이 없음 | 자동 표시 (frontmatter에 쓰지 않는다) |
| 초안 | 명세 작성 중 | `write-screen-spec` 저장 |
| 검토 | 기획·디자인 확인 중 | 확인 요청 시 |
| 확정 | 구현 가능 (Figma 노드·필수 섹션 채움) | `write-screen-spec` 확정 점검 통과 후 승인 |
| 구현완료 | 검수 결과가 "통과"이거나 승인받은 "조건부 통과" (`docs/QA.md` 4번, 결과는 화면 맵 "검수" 칸) | `implement-screen` 마무리 |
| 수정필요 | 원본의 새 버전 때문에 명세·퍼블을 다시 고쳐야 함 (확정·구현완료였던 화면만) | `version-update` 저장. 명세를 고쳐 확정 점검을 통과하면 "확정"으로 (`docs/changes/_index.md` 3번) |
