# PATTERNS.md — 화면 패턴

> 화면을 하는 일에 따라 몇 가지 패턴으로 나누고, 패턴마다 꼭 있어야 할 상태와 빠지기 쉬운 항목을 정한다.
> 화면마다 처음부터 판단하지 않고 패턴으로 빠짐없이 확인하기 위해서다.
> 화면의 패턴 원본은 플로우 문서 "2. 화면 목록" 표의 "패턴" 칸이다. 화면 명세는 그 칸을 읽어 쓴다. (명세에 다시 적지 않는다)
> IMPORTANT: 이 문서는 전체를 읽지 말고 필요한 패턴 절만 검색해 읽는다. (토큰 절감)

## 1. 패턴 목록
| 패턴 | 하는 일 | 필수 상태 | 자주 오는 앞 → 뒤 |
|---|---|---|---|
| 목록 | 같은 종류의 항목 여러 개를 보여주고 고르게 한다 | 기본 · 로딩 · 빈 값 · 에러 | → 상세 |
| 상세 | 항목 하나의 정보를 보여준다 | 기본 · 로딩 · 에러 | 목록 → |
| 입력 | 값을 입력·선택받는다 | 기본 · 에러(입력 검증) · 비활성(다음 버튼) | → 확인 |
| 확인 | 실행 전에 입력 내용을 보여주고 확정받는다 | 기본 · 로딩(실행 중) · 에러 | 입력 → 결과 |
| 결과 | 실행 결과를 알린다 | 기본(성공) · 에러(실패) · 처리 중(결과 미확정, 해당 시) | 확인 → |
| 검색 | 조건을 받아 결과 목록을 보여준다 | 기본(검색 전) · 로딩 · 빈 값(결과 없음) · 에러 | → 상세 |
| 안내 | 정보·안내만 보여준다 (이용 안내, 공지, 공통 오류 페이지 등) | 기본 (내용을 불러오면 로딩 · 에러) | |
| 동의 | 약관·동의 항목을 보여주고 동의받는다 | 기본 · 비활성(필수 미동의 시 다음 버튼) | → 입력 |

- 상태 이름은 `docs/DESIGN.md` 5번과 화면 명세 3번 상태 표를 따른다. "처리 중"처럼 패턴에만 있는 상태는 명세 3번 표에 줄을 더해 적는다.
- "점검" 상태는 모든 화면에 해당할 수 있어 패턴에 넣지 않는다. 처리 방법은 플로우 6번 예외 흐름(공통 화면)에서 정한다.

## 2. 패턴별 확인 항목
명세를 쓸 때 이 화면 패턴의 절만 읽고, 아래 항목이 명세에 있는지 확인한다. 자료로 답할 수 없으면 질문으로 남긴다. (지어내지 않는다)

### 목록
- 구성 영역: 목록 머리(건수·정렬·필터) / 항목 / 더 보기 또는 페이지 이동
- 빠지기 쉬운 항목
  - 빈 값 문구와 다음 행동(예: 등록 버튼)
  - 항목이 많을 때 방식(더 보기 / 무한 스크롤 / 페이지)과 한 번에 보이는 개수
  - 정렬·필터 기본값
  - 긴 텍스트 줄바꿈·말줄임 (`DESIGN.md` 6-2)
  - 항목을 눌렀을 때 이동 화면 (`data-screen-link`)

### 상세
- 구성 영역: 요약(핵심 값) / 정보 묶음 / 동작 버튼
- 빠지기 쉬운 항목
  - 값이 없을 때 표시 (예: "-")
  - 긴 값 줄바꿈
  - 가려야 하는 값 (해당 규칙 문서를 따른다)
  - 동작 버튼이 비활성·숨김이 되는 조건

### 입력
- 구성 영역: 입력 그룹 / 안내 문구 / 하단 버튼
- 빠지기 쉬운 항목
  - 필수·선택 표시
  - 입력 검증 규칙·시점·에러 문구 (명세 6번)
  - 기본값, 입력란 키보드 종류
  - 다음 버튼 활성 조건
  - 입력 중 이탈 확인 (플로우 7번)

### 확인
- 구성 영역: 확인할 값 목록 / 주의 문구 / 실행·수정 버튼
- 빠지기 쉬운 항목
  - 수정을 누르면 돌아갈 화면과 입력값 유지 여부
  - 실행 버튼 중복 클릭 방지, 실행 중 표시
  - 실행 전 추가 확인·인증 여부 (있으면 실행은 개발 몫, 퍼블은 표시까지)

### 결과
- 구성 영역: 결과 표시(성공·실패) / 결과 요약 / 다음 행동 버튼
- 빠지기 쉬운 항목
  - 실패 사유별 문구
  - 결과를 바로 알 수 없을 때(처리 중) 표시와 안내
  - 뒤로 가기 막기 (플로우 7번)
  - 다음 이동(홈·목록·이어서 하기)

### 검색
- 구성 영역: 검색 입력·조건 / 결과 목록 (결과 목록은 "목록" 절도 확인)
- 빠지기 쉬운 항목
  - 검색 전 화면 (예: 최근 검색어, 추천)
  - 결과 없음 문구
  - 검색 시작 조건 (최소 글자 수, 입력 즉시 / 버튼)
  - 조건 초기화

### 안내
- 구성 영역: 제목 / 본문 / 하단 버튼
- 빠지기 쉬운 항목
  - 긴 본문 스크롤과 하단 버튼 고정 여부
  - 본문 안 링크·전화번호 처리
  - 확인·닫기를 누른 뒤 이동 화면

### 동의
- 구성 영역: 전체 동의 / 항목별 동의(필수·선택 표시) / 약관 보기 / 다음 버튼
- 빠지기 쉬운 항목
  - 전체 동의와 항목별 동의의 연동
  - 필수·선택 구분과 다음 버튼 활성 조건
  - 약관 본문 보기 방식 (펼침 / 다른 화면 / 팝업)
  - 약관 문구는 지어내지 않는다. 원본이 없으면 질문으로 남긴다
  - 동의 기록·전송은 개발 몫

## 3. 쓰는 법
- 한 화면에 주된 패턴 하나만 적는다. 두 가지가 섞여 있으면 화면의 목적에 가까운 쪽을 고르고, 다른 패턴의 확인 항목은 함께 확인한다. (예: 검색 화면은 "목록" 절도 본다)
- 어느 패턴에도 맞지 않으면 "없음"이라고 적고, 확인 항목은 명세 작성 때 직접 정한다. 같은 일을 하는 화면이 여럿 생기면 4번 예외에 패턴을 추가한다.
- `write-flow` 2단계에서 기획서를 보고 패턴을 제안하고 승인받는다.
- `write-screen-spec`은 이 화면 패턴의 필수 상태로 명세 3번 표를 채우고, 확인 항목을 질문 목록에 넣는다. 확정 점검에서 필수 상태가 명세 3번에 없으면 "해당 없음"과 이유가 있어야 한다.
- 패턴 이름이 1번 표나 4번 예외에 없으면 `build-index` 훅이 경고한다.
