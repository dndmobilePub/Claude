# 변경 기록

> 입력 원본(IA·기획서·디자인)의 새 버전을 받았을 때 무엇이 바뀌었고 어디에 영향을 주는지 기록한다.
> 변경 기록은 `version-update` 스킬로만 만든다. 양식: `templates/change.md`
> 아래 "현황"은 `build-index` 훅이 자동 생성한다. 직접 고치지 않는다.
> IMPORTANT: 현황과 변경 기록은 전체를 읽지 말고 필요한 원본·버전·대상 행만 검색한다. (토큰 절감)

## 1. 기준 버전
현재 기준 버전의 원본은 원본마다 한 곳이다. 버전 이름은 웹 제작 프로젝트 팀이 부르는 이름을 그대로 쓴다. (예: v1.3, 2차 전달, 2025-11-03 전달분)

| 원본 | 현재 버전을 적는 곳 | 바꾸는 방법 |
|---|---|---|
| IA | `docs/ia/screen-list.md` frontmatter `version` | `ia-sync` (`version-update`가 부름) |
| 기획서 | `docs/storyboard/<도메인>.md` frontmatter `version` (도메인마다) | `write-flow` 0단계 (`version-update`가 부름) |
| 디자인 | 바로 아래 줄 (Figma에서 버전을 읽어 올 수 없어 사람이 정한 이름을 쓴다) | `version-update` |

- 디자인 기준 버전: [TODO: 예) 1차 전달. 디자인 원본이 아직 없으면 비워 둔다]

- 화면 명세는 frontmatter `ia_ver`·`plan_ver`·`design_ver`에 작성할 때 기준으로 삼은 버전을 적는다. 현재 버전과 다르면 훅이 경고한다.
- 이전 버전 원본은 따로 보관하지 않는다. 최신본만 두고, 이전 내용은 Git 기록(커밋·태그)으로 본다.

## 2. 변경 기록 파일
- 원본·버전마다 한 파일: `docs/changes/<원본>-<버전>.md` (원본 = `ia` | `plan` | `design`. 버전의 공백·`/`는 `-`로 바꾼다. 예: `ia-v1.3.md`, `design-2차-전달.md`)
- "2. 변경 목록" 표의 칸

| 칸 | 쓰는 법 |
|---|---|
| 구분 | 추가 / 삭제 / 수정 / 이동(다른 도메인·위치로) / 명칭 변경 |
| 대상 | 화면 ID, 컴포넌트 이름, 도메인 키, 토큰 이름, `공통` 중 하나 |
| 이전 · 이후 | 바뀐 내용 한 줄. 원본 내용을 길게 옮기지 않는다 |
| 영향 문서 | 영향받는 문서·폴더 경로. 없으면 `없음` |
| 처리 | 미처리 / 반영(영향 문서까지 고침) / 해당 없음 |

- 줄은 지우지 않는다. 처리 칸만 바꾼다.

## 3. 상태 "수정필요"
- 새 버전 때문에 다시 고쳐야 하는 문서의 상태. 화면·플로우·컴포넌트 명세 frontmatter `status`에 쓴다.
- "확정·승인·구현완료"인 문서만 "수정필요"로 바꾼다. 초안·검토인 문서는 상태를 두고 바로 고친다.
- 되돌리는 흐름
  - 화면: `write-screen-spec`으로 명세를 고침 → 확정 점검 → 확정 → `implement-screen`으로 다시 퍼블 → 구현완료
  - 플로우: `write-flow`로 고침 → 검토·확정
  - 컴포넌트: 명세를 고침 → 승인 → 다시 구현 → 구현완료
- 명세를 고쳐 반영했으면 변경 기록의 해당 줄 처리를 "반영"으로 바꾼다.

## 4. 다시 여는 질문
새 버전에서 확정된 질문의 답이 더 이상 맞지 않으면, 그 줄을 고치지 않고 새 질문을 만든다. (규칙: `docs/questions/_index.md` 3번)
