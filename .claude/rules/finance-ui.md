# 금융 UI 규칙

> 금융 서비스 화면에 공통으로 적용하는 규칙이다.
> 마스킹 범위·한도·타임아웃 시간처럼 기관마다 다른 값은 맨 아래 예외 섹션에 적는다. 값이 비어 있으면 추측하지 않고 묻는다.

## 1. 금액 표기
- IMPORTANT: 금액 포맷은 공통 유틸 함수 하나로만 처리한다. 화면마다 직접 포맷하지 않는다.
- 천 단위 구분 쉼표를 쓴다. 원화는 소수점 없이 표기한다.
- 통화 단위(원, USD 등)는 숫자와 함께 표기하고, 위치는 화면 전체에서 통일한다.
- 음수·출금·입금 표기(부호, 색)는 디자인 시스템 규칙을 따르고, 색만으로 구분하지 않는다.
- 금액 계산은 서버 값을 기준으로 한다. 화면에서 부동소수점 연산으로 금액을 만들지 않는다.

## 2. 금액 입력
- 숫자 키패드를 띄우고, 입력 중에도 쉼표를 표시한다. 저장·전송 값은 숫자만 남긴다.
- 한도·잔액 초과 등 검증 결과는 입력 근처에 즉시 안내한다.
- 큰 금액은 한글 금액(예: "1,000,000원 = 백만 원")을 보조 표시할지 프로젝트 규칙을 따른다.

## 3. 개인정보 마스킹
- IMPORTANT: 계좌번호, 카드번호, 주민등록번호, 전화번호, 이름 등 개인정보는 기본 마스킹으로 표시한다.
- 마스킹은 공통 유틸 함수 하나로 처리한다. 마스킹 범위는 프로젝트 예외 섹션을 따른다.
- "전체 보기"가 필요한 경우에만 사용자 동작으로 잠시 보여준다.
- 마스킹된 값도 스크린리더가 의미를 알 수 있게 읽힌다. (예: "계좌번호 끝자리 1234")

## 4. 보안 입력·데이터 처리
- 비밀번호·인증번호 입력은 프로젝트가 정한 보안 키패드·입력 컴포넌트만 쓴다.
- IMPORTANT: 개인정보·인증 정보를 `console.log`, URL 파라미터, localStorage/sessionStorage에 남기지 않는다.
- 입력값 자동완성은 보안 입력에서 끈다.
- 화면 캡처 방지 등 앱 수준 보안 요구는 프로젝트 예외 섹션을 따른다.

## 5. 중요 거래 확인
- 이체·해지·변경처럼 되돌리기 어려운 동작은 실행 전 확인 화면(받는 사람, 금액, 수수료 등)을 반드시 거친다.
- 실행 버튼은 중복 클릭을 막는다. (요청 중 비활성 + 로딩 표시)
- 결과 화면은 성공·실패·처리 중(결과 미확정)을 구분해 보여준다.

## 6. 에러·안내 문구
- 사용자가 할 수 있는 다음 행동을 함께 안내한다. (예: "잠시 후 다시 시도해 주세요", "고객센터 문의")
- 시스템 에러 코드·서버 메시지를 그대로 노출하지 않는다. 필요하면 문의용 코드만 작게 표시한다.
- 문구 톤과 고객센터 연락처는 프로젝트 예외 섹션을 따른다.

## 7. 세션·타임아웃
- 자동 로그아웃 전에 남은 시간을 알리고 연장할 수 있게 한다.
- 세션 만료 후에는 입력 중이던 민감 정보를 화면에서 지운다.

## 8. 점검·장애
- 서비스 점검·영업시간 외 이용 제한은 별도 상태로 구현한다. (DESIGN.md 상태 규칙의 "점검")

## 8-1. 공통 유틸 단위 테스트 (필수 항목)
금액·마스킹 유틸의 단위 테스트에는 아래 경우를 반드시 넣는다. (테스트 위치·실행 방법은 `docs/ARCHITECTURE.md` 3번)
- 금액 표시: 0, 음수, 천 단위 경계(999·1000), 큰 수(조 단위), 소수 있는 값(외화), 숫자가 아닌 값·빈 값
- 금액 입력: 쉼표 넣기·빼기, 붙여넣은 값, 최대 자릿수
- 마스킹: 길이가 짧은 값, 빈 값, 이미 마스킹된 값, 9번 예외의 범위대로 가려지는지
