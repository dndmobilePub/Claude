# 접근성 규칙

> 공통 기준: WCAG 2.1 AA 수준. 국내 서비스는 KWCAG(한국형 웹 콘텐츠 접근성 지침)도 함께 확인한다.
> 프로젝트가 따로 정한 기준·인증 대상이 있으면 맨 아래 예외 섹션에 적는다.

## 1. 의미 있는 마크업
- IMPORTANT: 클릭 요소는 `button`, 이동 요소는 `a`를 쓴다. `div`/`span`에 클릭 이벤트만 붙이지 않는다.
- 제목은 `h1`~`h6`를 순서대로 쓴다. 화면당 `h1`은 하나.
- 목록은 `ul`/`ol`, 표는 `table`(+`th`, `scope`)을 쓴다.
- 네이티브 요소로 해결되면 ARIA를 추가하지 않는다.

## 2. 텍스트 대체
- 의미 있는 이미지·아이콘 버튼에는 대체 텍스트(`alt`, `aria-label`)를 넣는다.
- 장식 이미지는 `alt=""` 또는 `aria-hidden="true"`로 숨긴다.
- 아이콘만 있는 버튼은 반드시 동작을 설명하는 레이블을 넣는다. (예: "닫기", "비밀번호 보기")

## 3. 키보드·포커스
- 모든 기능은 키보드만으로 쓸 수 있어야 한다.
- 포커스 표시를 제거하지 않는다. (`outline: none` 단독 사용 금지, 대체 스타일은 토큰으로)
- 포커스 순서는 화면 읽는 순서와 같게 한다. 양수 `tabindex` 금지.
- 모달·바텀시트: 열리면 내부로 포커스 이동, 열려 있는 동안 내부에 가둠, 닫으면 연 요소로 복귀, ESC로 닫기.

## 4. 폼
- 모든 입력에 보이는 레이블을 연결한다. placeholder를 레이블 대신 쓰지 않는다.
- 필수 항목은 시각 표시와 함께 프로그램으로도 알린다. (`aria-required` 또는 `required`)
- 에러는 해당 입력과 연결하고(`aria-describedby`), 색만으로 알리지 않는다.

## 5. 동적 변경 알림
- 토스트·에러·로딩 완료처럼 화면 일부가 바뀌면 `aria-live`로 알린다.
- 화면 전환 시 새 화면 제목으로 포커스 또는 안내를 준다.

## 6. 시각
- 명도 대비: 일반 텍스트 4.5:1, 큰 텍스트·UI 요소 3:1 이상. 토큰 조합이 기준에 못 미치면 보고한다.
- 색만으로 정보를 전달하지 않는다. (아이콘·텍스트 병행)
- 터치 영역은 충분히 크게 한다. 기준 크기는 디자인 시스템 토큰을 따른다.
- 글자 확대(200%) 시 내용이 잘리거나 겹치지 않게 한다.

## 7. 시간 제한
- 시간 제한이 있으면 남은 시간을 알리고, 연장할 방법을 제공한다. (업종 규칙에 시간 제한·세션 규칙이 있으면 함께 적용)
