# Figma → 코드 구현 규칙

> 토큰·컴포넌트·상태 규칙은 `docs/DESIGN.md`를 따른다. 이 파일은 구현 절차와 코드 작성 방식만 다룬다.
> Figma URL·토큰 위치는 `docs/PROJECT.md`를 따른다.

## 1. 구현 절차
1. IMPORTANT: 화면 명세(`docs/screens/<화면ID>.md`)의 Figma 노드 URL에서 fileKey·nodeId를 얻는다. URL이 없으면 구현하지 않고 묻는다.
2. Figma MCP 세션을 열고 해당 노드만 `get_design_context`로 조회한다.
3. 조회 결과는 **참고 코드**다. 그대로 붙여 넣지 않고 프로젝트 컴포넌트·토큰으로 바꿔 쓴다.
4. DESIGN.md 4번 순서로 컴포넌트를 매칭하고 조립한다.
5. `get_screenshot`으로 Figma와 구현 화면을 비교하고, 차이가 있으면 원인(토큰 누락·컴포넌트 차이)을 보고한다.

## 2. 조회 결과를 코드로 옮길 때
- Figma 결과에 나온 HEX·px 값은 대응하는 토큰으로 바꾼다. 대응 토큰이 없으면 멈추고 묻는다.
- 텍스트 레이어에 텍스트 스타일이 붙어 있으면 스타일 이름으로 토큰을 찾는다. (마크업은 `.text-<이름>` 클래스, 컴포넌트 스타일 안에서는 `--text-<이름>-*` 변수 — `DESIGN.md` 3-3) 그림자는 효과 스타일 이름으로 `--shadow-*`를 찾는다.
- Figma 변수에는 있는데 코드 토큰 파일에 없으면 토큰 파일을 직접 고치지 않고 `token-sync`를 안내한다. (`DESIGN.md` 3-1)
- 디자인 프레임 폭이나 프레임에 맞춘 Fixed 폭을 화면·영역의 width 고정값으로 옮기지 않는다. 화면 전체를 비율로 줄이지 않는다. (`DESIGN.md` 6-2)
- Figma 레이어 이름을 클래스명·변수명에 그대로 쓰지 않는다. 의미 있는 이름을 쓴다.
- 조회 결과의 언어(보통 React)와 스타일링 방식(예: Tailwind)이 프로젝트와 다르면 `docs/PROJECT.md`의 퍼블 언어·스타일링 방식으로 바꾼다.

## 3. 컴포넌트 작성
- 컴포넌트 위치·폴더 구조·네이밍은 `src/components/CLAUDE.md`를 따른다.
- 화면 컴포넌트는 조립만 한다. 디자인 값(색·간격)을 화면 파일에 직접 쓰지 않는다.

## 4. 에셋 (아이콘·이미지)
- 아이콘은 프로젝트의 기존 아이콘 컴포넌트·세트를 먼저 찾는다. 새 아이콘 패키지를 임의로 추가하지 않는다.
- Figma MCP가 에셋을 제공하면 그 에셋을 사용한다. 플레이스홀더 이미지나 임의 이미지를 넣지 않는다.
- 의미 있는 이미지는 대체 텍스트를 넣고, 장식 이미지는 스크린리더에서 숨긴다. (`a11y.md` 참조)
