# 버전 변경 절차

> 규칙 원본: `docs/changes/_index.md` (기준 버전, 변경 목록 칸, 수정필요 상태, 다시 여는 질문). 양식: `templates/change.md`
> 이 스킬은 **순서와 멈춤 지점**만 정한다. 원본 분석은 기존 스킬(`ia-sync`, `write-flow` 0단계, `token-sync`)을 그대로 부른다.
> 질문 기록 규칙: `docs/questions/_index.md`

## 입력
- 바뀐 원본: IA / 기획서 / 디자인. 한 번 실행에 원본 하나만 다룬다. 여럿이 함께 바뀌었으면 IA → 기획서 → 디자인 순서로 나눠 실행한다.
- 새 버전 이름: 팀이 부르는 이름 그대로 (예: v1.3, 2차 전달)
- 디자인이면: 디자이너의 변경 목록 (바뀐 화면·컴포넌트와 Figma 노드). 변수가 바뀌었는지도 확인한다.

## 원칙
- IMPORTANT: 입력 원본은 읽기만 한다. 원본끼리 다르거나 이상한 것은 고치지 않고 질문으로 남긴다.
- IMPORTANT: 영향받은 문서만 고친다. 영향 없는 문서는 기준 버전 표기만 올린다.
- 퍼블 파일(`src/`)은 이 스킬에서 고치지 않는다. 영향받은 화면은 "수정필요"로 두고 `implement-screen`으로 다시 퍼블한다.
- 이전 버전 원본·사본을 따로 보관하지 않는다. 이전 내용은 Git 기록으로 본다.
- 파일 저장 전에 보고하고 승인받는다.

## 멈춤 조건 (해당하면 즉시 멈추고 묻는다)
- 새 버전 이름을 모름, 또는 이전 기준 버전과 같음
- 작업 트리에 커밋되지 않은 변경이 있음 (특히 `docs/`·`src/`)
- 디자인인데 변경 목록이 없음 → 디자이너에게 요청하는 질문을 `docs/questions/design.md`에 남기고 멈춘다 (차단 "예"). 모든 화면을 다시 조회하지 않는다
- 기획서인데 "Figma 기획 설계서"와 "기획서 PPT"가 모두 "없음"
- 영향받은 화면 중 퍼블 작업이 진행 중인 화면(작업 브랜치가 열려 있음)이 있음 → 그 작업을 먼저 끝낼지 묻는다

## 단계

### 1. 사전 점검
- `docs/changes/_index.md` 현황에서 이 원본의 현재 기준 버전을 확인한다.
- 같은 원본·버전의 변경 기록 파일이 이미 있으면 새로 만들지 않고 이어서 진행한다.
- 브랜치 `docs/version-<원본>-<버전>`을 만든다. (`docs/GIT.md`) 이 스킬에서 부르는 스킬은 브랜치를 새로 만들지 않고 이 브랜치에서 각자 규칙대로 커밋한다.

### 2. 다시 분석 → 변경 목록 만들기
| 원본 | 방법 | 변경 목록의 근거 |
|---|---|---|
| IA | `ia-sync` 갱신 모드를 4단계(비교 보고)까지 진행한다. 사라지거나 바뀐 화면 ID의 사용처가 있어도 여기서는 멈추지 않고 영향 목록으로 넘긴다 | `ia-sync` 비교 보고 표 |
| 기획서 | 바뀐 도메인마다 `write-flow` 0단계로 `docs/storyboard/<도메인>.md`를 다시 만든다. 저장 전에 기존 사본과 비교한다 | 기존 사본과 새 초안의 차이 (화면 절 단위) |
| 디자인 | 변경 목록의 화면·컴포넌트마다 Figma 노드를 `get_metadata`·`get_screenshot`으로 확인하고, 명세 2번 구성·3번 상태와 비교한다. 변수가 바뀌었으면 `token-sync`를 4단계(비교 보고)까지 진행한다 | 디자이너 변경 목록 + 확인 결과, `token-sync` 비교 보고 |

- 결과를 `templates/change.md` 2번 표의 줄로 바꾼다. 처리 칸은 모두 "미처리"로 둔다.
- 원본 내용을 길게 옮기지 않는다. 이전·이후는 한 줄로 적는다.

### 3. 영향 범위 찾기
변경 줄마다 대상(화면 ID·컴포넌트 이름·도메인 키·토큰 이름)으로 아래만 검색한다. 문서 전체를 읽지 않는다.
- `docs/ui-flow/` (화면 목록 표·흐름), `docs/screens/`, `docs/components/`, `src/`
- `docs/questions/`의 확정 질문 중 대상이 같은 줄 (답이 새 버전과 맞지 않는지 4단계에서 판단)
- 찾은 경로를 변경 줄의 "영향 문서"에 적는다. 없으면 `없음`, 처리 "해당 없음".

### 4. 질문 정리
- **다시 여는 질문**: 확정 질문의 답이 새 버전과 맞지 않으면 그 줄은 고치지 않고 새 질문 줄을 만든다. 옛 줄은 `docs/questions/_index.md` 3번대로 닫는다.
- **원본 하나만 바뀜**: 예를 들어 IA 화면명이 바뀌었는데 기획서·디자인은 그대로면, 따라 바뀔 예정인지 `docs/questions/spec.md`에 질문으로 남긴다. 그 원본의 기준 버전은 올리지 않는다.
- 새로 만든 질문 ID를 변경 기록 3번에 적는다.

### 5. 보고 → 승인
아래 형식으로 보고하고 승인받는다. 바뀐 것이 없으면 "변경 없음"으로 보고하고, 기준 버전만 올릴지 묻는다.

### 6. 저장
승인받은 뒤 아래 순서로 진행한다.
1. 원본 사본을 저장한다: IA는 `ia-sync` 5~6단계, 기획서는 `write-flow` 0단계 저장(새 `version` 기재), 토큰은 `token-sync` 5~6단계. 디자인 기준 버전은 `docs/changes/_index.md` 1번 줄을 고친다.
2. `docs/changes/<원본>-<버전>.md`를 저장한다. (`_index.md` 2번 파일 이름 규칙)
3. 영향받은 문서를 처리한다. (`_index.md` 3번)
   - 상태가 확정·승인·구현완료인 문서: frontmatter `status`를 "수정필요"로 바꾼다. 본문은 여기서 고치지 않는다.
   - 상태가 초안·검토인 문서: 상태는 두고, 담당 스킬(`write-flow`·`write-screen-spec`)로 바로 고칠지 묻는다. 고치면 처리 "반영".
   - 화면 ID가 사라진 화면의 명세·폴더는 지우지 않는다. "수정필요"로 두고 처리 방법(삭제·다른 화면에 합침)을 질문으로 남긴다.
4. 영향 없는 화면 명세는 기준 버전만 올린다. `bump-ver.mjs`로 먼저 목록을 보고, 맞으면 `--write`로 쓴다.
   - 예: `node .claude/skills/version-update/bump-ver.mjs --key ia_ver --to v1.3 --from v1.2 --skip ACC-010,TRF-020`
   - 기획서는 `--key plan_ver --domain <도메인>`으로 도메인마다 실행한다.
5. `node .claude/hooks/build-index.mjs`를 실행해 현황을 다시 만들고 경고를 확인한다. (스크립트로 고친 파일은 훅이 자동으로 돌지 않는다)

### 7. 커밋
- `docs/GIT.md` 규칙을 따른다. 메시지 `docs(change): <원본> <버전> 반영`
- 사본 갱신(ia-sync·token-sync 커밋)과 변경 기록·상태 변경 커밋을 나눈다.
- PR 본문에 변경 수·수정필요 목록·새 질문을 적는다.

### 8. 다음 작업 안내
- "수정필요" 화면: `write-screen-spec`으로 명세를 고침 → 확정 → `plan-batch`로 "다시 퍼블" 묶음을 만듦 → `implement-screen <묶음 ID>`. 화면이 하나면 묶지 않고 `implement-screen <화면ID>`.
- 플로우: `write-flow` / 컴포넌트: 명세 수정 후 다시 구현
- 열린 차단 질문이 있으면 그 답을 먼저 받는다.

```
## 버전 변경: <원본> <이전 버전> → <새 버전>

- 수정필요로 바꿀 문서: 화면 n · 플로우 n · 컴포넌트 n / 바로 고칠 초안·검토 문서 n
- 버전만 올릴 화면 명세: n
- 질문: 다시 연 질문 n · 새 질문 n (차단 n)

| 구분 | 대상 | 이전 | 이후 | 영향 문서 | 처리 예정 |

| 명칭 변경 | TRF-010 | 이체 입력 | 이체 금액 입력 | ui-flow/transfer.md, screens/TRF-010.md, src/screens/transfer/TRF-010-* | 수정필요 |
| 수정 | ACC-020 | 잔액 표시 1줄 | 잔액·출금가능액 2줄 | screens/ACC-020.md | 수정필요 |
| 추가 | ACC-030 | — | 계좌 해지 | 없음 (플로우 등록 필요) | write-flow |
```
