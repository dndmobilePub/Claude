# 토큰 동기화 절차

> 변환 규칙 원본: `docs/DESIGN.md` 3-2(변수), 3-3(스타일), 9번(프로젝트별 값). Figma 변수 파일·스타일 파일·코드 토큰 위치는 `docs/PROJECT.md`.
> 이 스킬은 **작업 순서와 멈춤 지점**만 정한다. 변환은 AI가 손으로 하지 않고 `convert-tokens.mjs`가 한다. (토큰이 수백 개라 옮겨 쓰는 비용과 실수를 줄이기 위해)

## 입력
- 기본: 동기화 대상 컬렉션 전체 + 텍스트 스타일·그림자 효과 스타일 전체
- 컬렉션 이름을 지정받으면 그 컬렉션만 조회하고, 나머지 토큰은 기존 파일 내용을 그대로 둔다.
- 디자인 새 버전과 함께 변수가 바뀐 것이면 `version-update`로 시작한다. (`version-update`가 이 스킬을 부르고 영향받은 화면을 처리한다)

## 멈춤 조건 (해당하면 즉시 멈추고 묻는다)
- `docs/PROJECT.md`의 "Figma 변수 파일", "코드 토큰 위치", "퍼블 언어", "TypeScript" 중 하나가 [TODO]
- 변환한 이름이 서로 겹치거나, 한 이름이 값이면서 하위 단계를 가짐 (예: `color/primary`와 `color/primary/hover`)
- 이름에서 영문·숫자를 뺀 문자(한글 등)만 남아 이름을 만들 수 없음
- 별칭 대상이 동기화 범위 밖임 (다른 파일·라이브러리 변수, 찾을 수 없는 변수, 9번 제외 컬렉션의 변수). 게시에서 숨긴 변수는 동기화하는 변수가 가리키면 포함하므로 멈추지 않는다 (`DESIGN.md` 3-2)
- 모드가 2개 이상인 컬렉션이 둘 이상인데 `DESIGN.md` 9번에 컬렉션별 속성 이름이 없음, 또는 모드 이름을 코드 값으로 바꿀 수 없음 (예: 한글 모드 이름 → 9번 "모드 이름")
- 숫자 변수의 단위를 정할 수 없음 (→ 9번 "숫자 단위 지정")
- 스타일 토큰 이름이 변수 토큰 이름과 겹침, 또는 텍스트 스타일의 글꼴 스타일 이름을 굵기로 바꿀 수 없음
- 스타일에 연결된 변수가 동기화 범위 밖임
- 코드에서 쓰고 있는 토큰이 삭제되거나 이름이 바뀜

## 단계

### 1. 사전 점검
- `docs/PROJECT.md`의 네 값과 "Figma 스타일 파일", `docs/DESIGN.md` 9번 예외를 확인한다. 만들 파일은 `DESIGN.md` 3-2 "순서·파일" 표와 3-3 "파일"로 정한다.
- 작업 트리에 커밋되지 않은 변경이 있으면 알리고 진행 여부를 묻는다.
- 토큰 파일이 이미 있으면 맨 위의 "자동 생성" 표시를 확인한다. `git log`에 `chore(tokens)` 외의 커밋이 토큰 파일을 고친 기록이 있으면, 이번 동기화로 그 수정이 사라진다는 것을 먼저 알린다.

### 2. 내보내기 (읽기 전용)
- Figma MCP 규칙에 따라 `/figma-use` 스킬(없으면 `skill://figma/figma-use/SKILL.md`)을 먼저 읽고, 변수 파일로 세션을 연다.
- 처음이거나 컬렉션 구성을 모르면 `read-variables.js`(`COLLECTION_ID = null`)와 `read-styles.js`(`KIND = null`)로 컬렉션·모드·개수만 본다. 9번 값(모드 속성·모드 이름·제외·숫자 단위)이 필요하면 이때 묻고 9번에 적는다.
- 이 폴더의 `export-tokens.js`를 `use_figma`로 실행한다.
  1. `SKIP_COLLECTIONS`·`SKIP_STYLE_PREFIXES`를 9번 제외 값과 같게 넣는다.
  2. `PART = 0`부터 `parts - 1`까지 차례로 실행한다. (결과는 48KB까지라 조각으로 나뉜다)
  3. 받은 `text`를 순서대로 줄바꿈 하나로 이어 **저장소 밖 임시 파일**(예: `/tmp/token-export.txt`)에 **한 글자도 바꾸지 않고** 저장한다. 저장소에는 넣지 않는다. (원본은 Figma, 이력은 생성 파일의 git diff)
- 스타일 파일이 변수 파일과 다르면 그 파일에서도 실행해, 변수 파일 결과의 `#T`·`#E` 부분을 스타일 파일 결과로 바꿔 쓴다.
- IMPORTANT: 스크립트에 쓰기 코드를 넣지 않는다. 조회 결과가 이상해도 Figma를 고치지 않고 보고한다.
- `get_variable_defs`는 쓰지 않는다. 최종 값만 돌려주므로 별칭·모드를 만들 수 없다.

### 3. 변환·비교
- `node .claude/skills/token-sync/convert-tokens.mjs <임시 파일>`을 실행한다. (쓰지 않고 보고만 한다)
  - 첫 줄의 해시·줄 수가 맞지 않으면 옮겨 적다 틀린 것이다. 2단계에서 다시 받는다.
  - 결과: 변수·스타일 개수, 모드 블록, 만들 파일, 제외 목록(숨긴 변수 중 가리키는 것 없음, 불리언, 블러, 9번 제외), 기존 파일과의 차이(추가·값 변경·삭제)
  - 삭제되는 토큰은 퍼블 소스 폴더에서 사용처를 찾아 함께 보고한다. 사용처가 있으면 멈춤이다.
- 멈춤 조건이 나오면 파일을 쓰지 않고 끝난다. 9번 값으로 풀 수 있는 것(모드 속성·모드 이름·숫자 단위·제외)은 묻고 9번에 적은 뒤 다시 실행한다. Figma 이름을 고쳐야 하는 것은 `docs/questions/design.md`에 질문으로 남긴다.
- 삭제 토큰 사용처가 있으면 선택지(Figma 이름 복구 / 사용처를 새 토큰으로 교체 / 디자이너 확인)를 받는다. 교체는 이 스킬에서 하지 않고 별도 작업으로 나눈다.

### 4. 보고 → 승인
- 3단계 출력을 아래 보고 형식으로 요약해 보여주고 승인받는다. 바뀐 것이 없으면 "변경 없음"으로 보고하고 끝낸다.

### 5. 작성
- 승인받은 뒤 같은 명령에 `--write`를 붙여 실행한다. 스크립트가 토큰 파일을 모두 통째로 새로 쓴다. 토큰 파일을 손으로 고치지 않는다.
- `docs/PROJECT.md`의 린트/테스트 명령으로 타입·문법 오류를 확인한다.
- 임시 파일은 지워도 된다.

### 6. 커밋
- `docs/GIT.md` 규칙을 따른다. 브랜치는 `docs/GIT.md`(7번 예외 포함)를 따른다. 예) 브랜치 `chore/token-sync`. 메시지 `chore(tokens): Figma 변수 동기화`
- 커밋 본문에 변수·스타일별 추가·변경·삭제 개수와 Figma 변수·스타일 파일 이름을 적는다.
- 토큰 파일 외의 변경을 같은 커밋에 넣지 않는다. (`text-styles.css`는 토큰 파일로 본다)

## 보고 형식
```
## 토큰 동기화 비교 (Figma 변수 파일: <파일 이름>)
- 컬렉션: <이름(모드 목록)>, ... / 스타일: 텍스트 n · 그림자 n (Figma 스타일 파일: <파일 이름>)
- 변수: 추가 n / 값 변경 n / 삭제 n / 이름 변경 의심 n / 제외 n
- 스타일: 추가 n / 값 변경 n / 삭제 n / 이름 변경 의심 n / 제외 n (블러 n)

| 구분 | 토큰 | 이전 | 이후 | 사용처 |
|---|---|---|---|---|
| 추가 | `--color-text-brand` | — | `var(--blue-500)` | — |
| 값 변경 | `--spacing-4` | `16px` | `20px` | — |
| 삭제 | `--color-bg-muted` | `var(--gray-50)` | — | 3곳 (멈춤) |

- 이름 변경 의심: 삭제된 토큰과 값이 같은 추가 토큰 쌍
- 결정 필요: (있으면)
```
