# 토큰 동기화 절차

> 변환 규칙 원본: `docs/DESIGN.md` 3-2. Figma 변수 파일·코드 토큰 위치는 `docs/PROJECT.md`.
> 이 스킬은 **작업 순서와 멈춤 지점**만 정한다.

## 입력
- 기본: 동기화 대상 컬렉션 전체
- 컬렉션 이름을 지정받으면 그 컬렉션만 조회하고, 나머지 토큰은 기존 파일 내용을 그대로 둔다.
- 디자인 새 버전과 함께 변수가 바뀐 것이면 `version-update`로 시작한다. (`version-update`가 이 스킬을 부르고 영향받은 화면을 처리한다)

## 멈춤 조건 (해당하면 즉시 멈추고 묻는다)
- `docs/PROJECT.md`의 "Figma 변수 파일", "코드 토큰 위치", "퍼블 언어", "TypeScript" 중 하나가 [TODO]
- 변환한 이름이 서로 겹치거나, 한 이름이 값이면서 하위 단계를 가짐 (예: `color/primary`와 `color/primary/hover`)
- 이름에서 영문·숫자를 뺀 문자(한글 등)만 남아 이름을 만들 수 없음
- 별칭 대상이 동기화 범위 밖임 (다른 파일·라이브러리 변수, 게시에서 숨긴 변수, 찾을 수 없는 변수)
- 모드가 2개 이상인 컬렉션이 둘 이상인데 `DESIGN.md` 9번에 컬렉션별 속성 이름이 없음
- 숫자 변수의 단위를 정할 수 없음
- 코드에서 쓰고 있는 토큰이 삭제되거나 이름이 바뀜

## 단계

### 1. 사전 점검
- `docs/PROJECT.md`의 네 값과 `docs/DESIGN.md` 9번 예외를 확인한다. 만들 파일은 `DESIGN.md` 3-2 "순서·파일" 표로 정한다.
- 작업 트리에 커밋되지 않은 변경이 있으면 알리고 진행 여부를 묻는다.
- 토큰 파일이 이미 있으면 맨 위의 "자동 생성" 표시를 확인한다. `git log`에 `chore(tokens)` 외의 커밋이 토큰 파일을 고친 기록이 있으면, 이번 동기화로 그 수정이 사라진다는 것을 먼저 알린다.

### 2. 조회 (읽기 전용)
- Figma MCP 규칙에 따라 `/figma-use` 스킬(없으면 `skill://figma/figma-use/SKILL.md`)을 먼저 읽고, 변수 파일로 세션을 연다.
- 이 폴더의 `read-variables.js`를 `use_figma`로 실행한다.
  1. `COLLECTION_ID = null` → 컬렉션 목록 (이름·모드·기본 모드·변수 개수·숨김 여부)
  2. 대상 컬렉션마다 `COLLECTION_ID`를 넣어 실행하고, 결과의 `next`가 null이 될 때까지 `OFFSET = next`로 반복한다.
- IMPORTANT: 스크립트에 쓰기 코드를 넣지 않는다. 조회 결과가 이상해도 Figma를 고치지 않고 보고한다.
- 조회 결과는 대화에만 두고 파일로 저장하지 않는다. (원본은 Figma, 이력은 생성 파일의 git diff)
- `get_variable_defs`는 쓰지 않는다. 최종 값만 돌려주므로 별칭·모드를 만들 수 없다.

### 3. 변환
- `DESIGN.md` 3-2 규칙으로 토큰 파일 내용(`tokens.css`, 참조 파일이 필요하면 `tokens.ts` 또는 `tokens.js`)을 만든다. 아직 파일에 쓰지 않는다.
- 제외 대상(게시에서 숨긴 컬렉션·변수, 불리언 변수, 9번 예외의 제외 컬렉션)은 따로 목록으로 남긴다.

### 4. 비교 보고 → 승인
- 기존 토큰 파일과 비교해 아래 형식으로 보고한다. 기존 파일이 없으면 "최초 생성"으로 표시하고 개수만 보고한다.
- 삭제·이름 변경 토큰은 Grep으로 사용처를 찾는다. CSS 변수(`--이름`)와 참조 파일 사용(`tokens.경로`, `tokens.경로['키']`, 참조 파일이 있을 때만) 두 형태를 모두 찾고, 토큰 파일 자체는 제외한다.
- 사용처가 있으면 멈춤 조건이다. 사용처 목록을 보여주고 선택지(Figma 이름 복구 / 사용처를 새 토큰으로 교체 / 디자이너 확인)를 받는다. 교체는 이 스킬에서 하지 않고 별도 작업으로 나눈다. 디자이너 확인을 기다려야 하면 `docs/questions/design.md`에 질문으로 남긴다. (규칙: `docs/questions/_index.md`)
- 바뀐 것이 없으면 "변경 없음"으로 보고하고 끝낸다.

### 5. 작성
- 승인받은 뒤 토큰 파일을 모두 통째로 새로 쓴다. 일부만 고치지 않는다.
- `docs/PROJECT.md`의 린트/테스트 명령으로 타입·문법 오류를 확인한다.

### 6. 커밋
- `docs/GIT.md` 규칙을 따른다. 브랜치 `chore/token-sync`, 메시지 `chore(tokens): Figma 변수 동기화`
- 커밋 본문에 추가·변경·삭제 개수와 Figma 변수 파일 이름을 적는다.
- 토큰 파일 외의 변경을 같은 커밋에 넣지 않는다.

## 보고 형식
```

- 컬렉션: <이름(모드 목록)>, ...
- 추가 n / 값 변경 n / 삭제 n / 이름 변경 의심 n / 제외 n

| 구분 | 토큰 | 이전 | 이후 | 사용처 |
|---|---|---|---|---|
| 추가 | `--color-text-brand` | — | `var(--blue-500)` | — |
| 값 변경 | `--spacing-4` | `16px` | `20px` | — |
| 삭제 | `--color-bg-muted` | `var(--gray-50)` | — | 3곳 (멈춤) |

- 이름 변경 의심: 삭제된 토큰과 값이 같은 추가 토큰 쌍
- 결정 필요: (있으면)
```
