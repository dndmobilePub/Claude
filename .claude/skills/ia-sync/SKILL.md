# IA 동기화 절차

> 양식: `templates/ia-source.md`(읽는 방법), `templates/ia-screen-list.md`(사본). 읽기 스크립트: `read-ia.mjs`.
> 이 스킬은 **작업 순서와 멈춤 지점**만 정한다. IA 양식은 프로젝트마다 다르므로 칼럼 이름·위치를 가정하지 않고 `docs/ia/source.md`에 기록된 대로 읽는다.
> 질문 기록 규칙: `docs/questions/_index.md` (IA에서 생긴 질문은 `docs/questions/ia.md`)

## 입력
- IA 파일: `docs/PROJECT.md`의 "IA 파일"
- 모드: 처음(읽는 방법이 없음) / 갱신(읽는 방법이 있음)
- IA의 새 버전을 받은 것이면 이 스킬을 직접 쓰지 않고 `version-update`로 시작한다. (`version-update`가 이 스킬의 갱신 모드를 부르고, 영향받은 플로우·명세를 처리한다)

## 원칙
- IMPORTANT: IA에 적힌 값을 고치거나 채우지 않는다. 빈 화면 ID에 ID를 지어 붙이지 않는다. 이상한 것은 묻고, 답이 없으면 `docs/questions/ia.md`에 남긴다.
- IMPORTANT: IA 원본 파일은 읽기만 한다. 수정·다른 이름으로 저장하지 않는다.
- `docs/ia/screen-list.md`는 손으로 고치지 않는다. 이 스킬로만 만든다.
- 스크립트 출력은 대화에만 두고 파일로 저장하지 않는다. (원본은 IA, 이력은 사본의 git diff)
- 파일 저장 전에 초안을 보여주고 승인받는다.

## 멈춤 조건 (해당하면 즉시 멈추고 묻는다)
- `docs/PROJECT.md`의 "IA 파일"이 [TODO]이거나 파일을 찾을 수 없음 ("없음"이면 이 스킬을 쓰지 않는다. 화면 목록 원본은 플로우 문서)
- 파일이 .xls(옛 형식) — .xlsx로 다시 저장해 달라고 요청한다
- 갱신 모드인데 `source.md`의 시트·머리글·열이 실제 IA와 다름 (IA 양식이 바뀜) → 2단계부터 다시
- 화면 ID가 중복되거나, `docs/PROJECT.md` "화면 ID 형식"과 맞지 않거나, 파일 이름에 쓸 수 없는 문자(공백 `/ \ : * ? " < > |`)가 있음
- 도메인 기준 값 중 `source.md` 3번 도메인 대응에 없는 값이 있음
- WBS 표시를 날짜로 바꿀 수 없음 (환산 규칙이 없거나 맞지 않음)
- 이미 플로우·명세에 쓰인 화면 ID가 IA에서 사라지거나 바뀜 → 영향 목록을 보여주고 멈춘다

## 단계

### 1. 사전 점검
- `docs/PROJECT.md`의 "IA 파일", "화면 ID 형식"을 확인한다.
- `docs/ia/source.md`가 있으면 갱신 모드, 없으면 처음 모드다.
- 갱신 모드면 `docs/ia/screen-list.md`의 `version`·`analyzed`를 알리고, IA가 바뀌었는지 묻는다. 바뀌지 않았으면 끝낸다.
- 작업 트리에 커밋되지 않은 `docs/ia/` 변경이 있으면 알리고 진행 여부를 묻는다.

### 2. 구조 파악 (처음 모드, 또는 양식이 바뀐 갱신 모드)
`read-ia.mjs`로 조금씩 읽는다. 한 번에 전체를 출력하지 않는다. (토큰 절감)
1. `node .claude/skills/ia-sync/read-ia.mjs <파일> sheets` → 시트 목록. 화면 목록·WBS가 있는 시트를 고른다. 숨김 시트·변경 이력 시트는 사용자에게 용도를 확인한다.
2. `dump --sheet <시트> --rows 1-15` → 머리글 행과 데이터 시작 행을 찾는다. 열이 많으면 `--cols`로 나눠 본다.
3. 머리글을 보고 `templates/ia-source.md` 1번 표준 항목에 대응하는 열을 제안한다. 비슷한 이름이 여러 개면 추측하지 않고 묻는다.
4. 도메인 기준 열의 값 목록을 뽑아 3번 도메인 대응(도메인 키·이름·약어)을 제안한다. 기존 플로우 문서가 있으면 그 파일 이름을 도메인 키로 쓴다.
5. WBS가 있으면 `fills --sheet <시트> --rows <머리글~데이터 일부>`(색칠) 또는 `dump`(문자 표시·날짜 열)로 표시 방식을 확인한다.
   - 색키마다 어떤 단계(예: 기획·디자인·퍼블·검수)인지 묻는다. 범례가 시트 안에 있으면 그것을 근거로 제안한다.
   - 날짜 머리글(월·주차·날짜)과 한 칸 단위를 확인하고, 연도·주 시작 요일 같은 환산 규칙을 묻는다.
   - 현황에 표시할 단계를 묻는다.
6. 제외할 행 조건(삭제 표시, 취소선 `~~값~~`, 숨김 행 `(숨김)`, 소제목 행 등)을 확인한다.
7. 버전 확인 방법을 정한다.
8. `docs/ia/source.md` 초안을 보여주고 승인받은 뒤 저장한다.

### 3. 추출
- `source.md` 범위대로 `dump`를 `--rows`로 나눠 읽는다. 출력 마지막 줄의 `# 다음:` 값으로 이어 읽는다.
- 병합 셀은 스크립트가 위 값으로 채운 값을 쓴다. (`source.md`가 다른 방법을 정했으면 `--raw`로 읽고 그 방법을 따른다)
- 행마다 표준 항목을 꺼내고, 제외 조건에 맞으면 "제외한 행"으로 보낸다.
- WBS는 화면 행마다 단계별 시작·종료일로 바꾼다. 같은 단계가 떨어진 두 구간이면 두 줄로 쓴다.
- 멈춤 조건에 걸리는 값은 고치지 않고 질문 목록에 모은다. (출처 위치는 `시트!셀` 또는 `시트!행`)

### 4. 비교 보고 → 승인
- 처음 모드: 화면 수(도메인별), 일정이 있는 화면 수, 제외한 행 수, 질문 목록을 보고한다.
- 갱신 모드: 기존 사본과 비교해 아래 형식으로 보고한다.
  - 사라진·ID가 바뀐 화면은 플로우·명세 사용처를 Grep으로 찾는다. (`docs/ui-flow/`, `docs/screens/`, `src/`) 사용처가 있으면 멈춤 조건이다.
- 질문은 한 번에 묶어 묻는다. 답으로 해결된 것만 반영하고, 나머지는 `docs/questions/ia.md`에 한 줄씩 남긴다. (차단: 화면 ID가 없거나 중복이면 "예")
- IA 값이 틀린 것으로 확인돼도 사본에서 고치지 않는다. IA 원본 수정을 요청하고, 고쳐진 IA로 다시 동기화한다.

### 5. 저장
- 승인받은 뒤 `docs/ia/screen-list.md`를 통째로 새로 쓴다. 일부만 고치지 않는다. frontmatter `version`·`analyzed`를 채우고 템플릿 주석은 지운다.
- 저장하면 `build-index` 훅이 화면 맵을 IA 기준으로 다시 만든다. 경고(플로우와 다른 화면명·도메인, IA에 없는 화면 등)가 나오면 보고하고, 플로우를 고칠지 승인받는다. (플로우 수정은 `write-flow`로)

### 6. 커밋
- `docs/GIT.md` 규칙을 따른다. 브랜치 `docs/ia-sync`, 메시지 `docs(ia): IA <버전> 동기화`
- 커밋 본문에 추가·변경·제외 개수를 적는다. 사본 외의 변경을 같은 커밋에 넣지 않는다. (`source.md`를 처음 만들었거나 `docs/questions/ia.md`를 고쳤으면 함께 넣는다)

