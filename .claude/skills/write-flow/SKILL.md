# 플로우 작성 절차

> 양식: `templates/flow.md`, 설계서 분석 `templates/storyboard.md`. 조회 스크립트: `read-storyboard.js`. 화면 ID 체계·상태 정의: `docs/ui-flow/_index.md`.
> 이 스킬은 **화면 사이의 이동**만 다룬다. 화면 안의 내용은 `write-screen-spec`이 맡는다.

## 입력
- 도메인 이름 (예: 이체)
- Figma 기획 설계서: `docs/PROJECT.md`의 "Figma 기획 설계서" 중 이 도메인의 페이지·섹션
- 참고 자료 (있으면): 사용자 설명, 기획 문서

## 원칙
- IMPORTANT: 업무 규칙·분기 조건을 지어내지 않는다. 자료에 없으면 질문하고, 답이 없으면 "미결 사항"에 남긴다.
- IMPORTANT: Figma는 읽기만 한다. 기획 설계서·디자인을 새로 그리거나 고치지 않는다.
- 기획 설계서는 0단계에서 한 번 분석해 md로 남기고, 이후 단계는 그 md만 읽는다. 디자인 파일 세부는 이 스킬에서 조회하지 않는다. (토큰 절감)
- 파일 저장 전에 전체 초안을 보여주고 승인받는다.

## 단계

### 0. 기획 설계서 분석
- `docs/PROJECT.md`의 "Figma 기획 설계서"가 "없음"이면 이 단계를 건너뛴다. (md를 만들지 않고 사용자 설명·문서로 진행)
- `docs/storyboard/<도메인>.md`가 있으면 `analyzed` 일자를 알리고 원본이 바뀌었는지 묻는다. 바뀌지 않았으면 md만 쓰고 이 단계를 마친다.
- 없거나 바뀌었으면 `read-storyboard.js`로 조회한다.
  1. `NODE_ID = null`로 페이지·프레임 목록을 받고, 이 도메인에 해당하는 페이지·섹션을 확인받는다.
  2. 그 노드로 텍스트를 읽는다. `next`가 있으면 이어서 읽는다.
  3. 텍스트만으로 이해할 수 없는 프레임(흐름 도식 등)만 `get_screenshot`으로 확인한다.
- `templates/storyboard.md` 양식으로 초안을 만들어 보여주고 승인받은 뒤 저장한다.
- 설계서에 없는 내용은 채우지 않는다. 해석이 필요한 것은 "확인 필요"에 남기고, 4단계 질문 목록에 함께 넣는다.

### 1. 사전 확인
- `docs/ui-flow/_index.md`에서 도메인 약어와 기존 플로우를 확인한다. 약어가 없으면 제안하고 승인받는다.
  - 현황 표는 전체를 읽지 않고 이 도메인의 약어로 검색해 기존 화면 ID만 확인한다.
- `docs/PRODUCT.md`에서 이 도메인과 관련된 섹션(용어·비즈니스 규칙)만 읽는다.
- 같은 도메인 플로우가 이미 있으면 새로 만들지 않고 수정으로 진행한다.

### 2. 화면 목록 초안 → 승인
- 자료에서 화면을 뽑아 목록을 만든다.

  | 제안 화면 ID | 화면명 | 역할 | 근거 (설계서 프레임·자료) |
  |---|---|---|---|

- 화면 ID 번호는 10 단위로 붙인다. (예: TRF-010, TRF-020 — 나중에 사이에 끼워 넣기 위해)
- 공통 화면(에러, 점검, 세션 만료)은 도메인 화면으로 만들지 않고 공통 화면으로 참조한다.

### 3. 흐름 초안
- 하위 흐름(4번)으로 나눈 뒤 Mermaid 흐름도(3번)를 그린다. 화면이 15개를 넘으면 하위 흐름별로 나눠 그린다.
- 분기 지점마다 조건과 이동 화면을 표(5번)로 정리한다.

### 4. 빠지기 쉬운 항목 확인
아래를 하나씩 확인하고, 자료로 답할 수 없는 것은 질문 목록으로 모아 한 번에 묻는다.
- 전제 조건을 충족하지 못했을 때 (미로그인, 인증 안 됨, 대상 상품 없음)
- 예외·에러 흐름 (세션 만료, 점검, 네트워크 오류, 인증 실패, 도메인 고유 실패)
- 뒤로 가기, 입력 중 이탈, 완료 후 뒤로 가기
- 중간 저장·이어하기 여부
- 플로우 밖으로 나가는 지점과 돌아오는 지점

### 5. 초안 제시 → 승인 → 저장
- 완성된 초안 전체를 보여주고 승인받는다.
- 승인 후:
  - `docs/ui-flow/<도메인>.md`로 저장한다. frontmatter(`domain`, `code`, `status: 초안`, `updated`)를 채우고 템플릿 주석은 지운다.
  - storyboard md의 각 화면 절 "화면 ID"를 채운다. (플로우 초안과 함께 승인)
  - `_index.md`는 고치지 않는다. 저장하면 `build-index` 훅이 화면 목록 표를 읽어 현황에 "명세 전"으로 등록한다.
  - 훅이 불일치 경고(ID 중복, 약어 불일치 등)를 내면 보고하고, 고칠지 승인받는다.

## 완료 보고 형식
```
## <도메인> 플로우 작성 결과
- 파일: docs/ui-flow/<도메인>.md (상태: 초안)
- 설계서 분석: docs/storyboard/<도메인>.md (분석일 YYYY-MM-DD / 없음)
- 화면: n개 (ID 범위)
- 하위 흐름: n개
- 미결 사항: n건 (목록)
- 다음 작업: write-screen-spec으로 화면 명세 작성 (권장 순서: 하위 흐름 4.1부터)
```
